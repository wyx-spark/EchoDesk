# EchoDesk 自动化配置填写指南

这份指南手把手教你把「浏览器自动化」配好：让 EchoDesk 自己打开你单位的网页、逐个点开任务、
把附件下载下来，交给本机模型生成审核意见，并把结果**整整齐齐地**放进文件夹。

不需要懂编程，也不需要懂网页。凡是必须说清楚原理的地方，指南里都会给出「点哪里、填什么」的具体做法。

English version: [`docs/en/AUTOMATION_GUIDE.md`](../en/AUTOMATION_GUIDE.md)（本文为英文版的中文参考译本，如两者有歧义，**以英文版为准**）。
相关文档：[用户手册](USER_GUIDE.md) · [常见问题](FAQ.md) · [技能开发指南](SKILL_GUIDE.md)。

> **⚠️ 本功能仅 Windows 可用：macOS 与 Linux 上不提供浏览器自动化。**
>
> 自动化通过 Playwright 驱动**本机的 Microsoft Edge**（有头运行、复用登录态），它的配置页也属于
> Windows 专属界面。**macOS 与 Linux 上完全不提供该功能**：自动化页面不会出现，请求该能力时回答是
> `Windows-only capability (this is not a missing dependency)`（仅 Windows 提供该能力，不是依赖缺失问题）
> ——这是刻意的：**不是**装坏了、**不是**少装了一个包，也**不是** `pip install` 能解决的问题。
>
> **替代做法**（按大多数人的实际顺序）：用 **MCP Server** 把浏览器操作暴露成智能体可调用的工具；
> 用**技能**完成同一套流程并按内置自动化的格式返回结果；或者**在一台 Windows 机器上跑完自动化，
> 把结果目录导出**到你实际工作的机器上。下载之后的环节——解析、检索、审核、报告——全部保持跨平台，
> 所以在 Windows 上产出的 `results/` 目录拿到哪个平台都能看。
>
> 因此本文其余部分说明的是 **Windows** 上的配置界面。真正因平台而不同的路径（首要是结果保存位置）
> 会三平台并列给出。权威说明见 [`CROSS_PLATFORM.md`](CROSS_PLATFORM.md) 第 3.2 与第 5 节。

**本文里的路径怎么写**：程序目录内部的路径统一用正斜杠（`app/backend/config.json`）——macOS 与 Linux 上
就是这样显示的，Windows 上同一条路径写作 `app\backend\config.json`。真正因平台而不同的只有**结果根目录**，
因为各平台把用户数据放在各自约定的位置（见 3.9 与 4.3）。

## 一、开始之前

### 1.1 三件必须准备的事

| 准备项 | 说明 | 怎么确认 |
| --- | --- | --- |
| **Windows** —— 浏览器自动化仅 Windows 提供（见上方提醒；macOS/Linux 上不提供本功能） | 自动化驱动的是 Windows 上那套 Edge，配置页本身也属于 Windows 专属界面 | macOS/Linux 上没有可配置的东西——请改用上方列出的替代做法 |
| 本机已安装受支持的浏览器 | 自动化用系统里的浏览器打开网页（配置项 `browser` 默认 `auto`，依次尝试 **Edge → Chrome → 内置 Chromium → Firefox**，用第一个能起来的），不使用无头模式 | 能正常打开 Edge 或 Chrome 即可；两个都没装时程序会自动用自带的 Chromium |
| 已下载本地模型 | 生成审核意见要用本地模型；没模型时会提示「未加载本地模型，无法生成摘要与审核意见」 | 主窗口 `/status` 能看到已加载的模型 |
| 本机能正常访问那个网页系统 | 包括登录、权限、内网/VPN；自动化只是替你点鼠标，它访问不了的地方也到不了 | 用 Edge 手动打开一次任务列表页，确认能看到任务 |

如果任务里的附件是 `.doc` / `.ppt` 这类旧格式，或需要读取加密文档，本机还要装有 **WPS 或 Microsoft Office**（用于 COM 读取）。
这一项同样是 **Windows 专属**：在没有 COM 接口的平台上，程序会明确提示「该能力仅 Windows 提供」，
替代做法是在 Windows 机器上用 WPS/Office 另存为未加密文件或 `.docx`、通过 MCP/技能转换，
或安装一个自带该格式解析器的技能——**不会**让你去装 WPS 再重试，那在那些平台上纯属白费功夫。

### 1.2 自动化到底做了什么

点「▶ 立即运行一次」之后，程序会：

1. **有头打开浏览器**（你全程看得见），访问你填的任务列表网址；**登录状态自动复用**——
   第一次在这个浏览器窗口里登录一次即可，之后每次运行都不用再登录（见第十节）；
2. 按「任务列表元素位置」找出所有任务链接（相对路径会补全成绝对地址；`javascript:` / `#` / 空 href
   这类伪链接会自动改为点击，见第十一节），按「下一页按钮」自动翻页（如果填了）；
3. 逐个进入任务详情页，按「任务详情页文件元素位置」找出附件，只下载后缀在「需要预览的文件后缀」里的文件；
4. 在本地解析附件内容，连同「任务指令」一起交给本地模型，生成审核意见；
5. 把原始附件与结果留下来（存到结果目录），继续下一个任务；
6. 每个任务都往审计日志里写一条记录（见第九节）。

遇到验证码或二次验证会**暂停等你手动完成**（默认最多等 180 秒）。

### 1.3 五分钟上手路径

1. 打开**设置窗口 → 自动化**；
2. 从上往下填「任务列表网址 → 任务列表元素位置 → 任务详情页文件元素位置 → 需要预览的文件后缀 → 任务指令」；
3. 点**「测试选择器」**，按向导一步步走完（第五节有详细流程）；
4. 勾选**安全协议**，再打开**自动化总开关**；
5. 点**「▶ 立即运行一次」**，先看一两个任务的处理过程，确认结果目录里的东西是你想要的。

> 📷 屏幕上该看什么：设置窗口「自动化」标签页的整体界面——安全协议区、各字段的位置、
> 右侧的「测试选择器」按钮，以及下方的「▶ 立即运行一次 / ⏹ 停止自动化 / 运行日志」区域。> 📷 **v0.2.1 不含截图。** 下列界面预览会在后续版本放入 `assets/screenshots/`，
> 在此之前，这段文字说明的是屏幕上该看什么。

## 二、字段总览表

### 2.1 必填字段（不填就跑不起来）

| 界面上/配置里的名字 | 是否必填 | 作用 | 默认值 |
| --- | --- | --- | --- |
| 任务列表网址 `task_list_url` | **必填** | 打开后能看到全部任务的页面地址 | 空 |
| 任务列表元素位置 `task_list_selector` | **必填** | 告诉程序「任务链接」在页面上的位置，程序靠它找到每个任务 | 空 |
| 任务详情页文件元素位置 `task_detail_file_selector` | **必填** | 告诉程序点进任务后，附件名称在页面上的位置 | 空 |
| 需要预览的文件后缀 `file_extensions` | **必填** | 只处理这些类型的文件，其他一概跳过 | `pdf, docx, doc, xlsx, xls, pptx, ppt, txt` |
| 任务指令 `instruction` | **必填**（有默认值） | 告诉 AI 要对文件做什么、生成什么意见 | 摘取合同的主要信息并生成财务审核意见 |
| 安全协议 `safety_accepted` | **必填** | 自动化的前置条件；不勾选则总开关无法生效 | `false` |
| 自动化总开关 `enabled` | 要跑就必须开 | 打开后才会实际执行；未勾选安全协议时会被强制关闭 | `false` |

### 2.2 可选字段（设置窗口里就能改）

| 界面上/配置里的名字 | 是否必填 | 作用 | 默认值 |
| --- | --- | --- | --- |
| 任务行容器 `task_row_selector` | 可选 | 一个任务在页面上是一整行（如表格的一行）时填它，定位更准；不确定就留空 | 空 |
| 下一页按钮 `next_page_selector` | 可选 | 任务列表有多页时填它，程序会自动翻页；只有一页就留空 | 空 |
| 最多任务数 `max_tasks` | 可选 | 一轮最多处理几个任务，避免一次跑太多 | `20`（1–500） |
| 页面超时(ms) `page_timeout_ms` | 可选 | 打开网页最多等多久；内网系统慢就调大 | `30000`（3000–300000） |
| 重试次数 `retries` | 可选 | 某个任务失败后自动重试几次 | `1`（0–5） |
| 任务去重 `dedupe` | 可选 | 勾选后，处理过的任务下次自动跳过 | `true` |
| 保存结果到本地文件 `save_results` | 可选 | 取消勾选就只做试运行，不写任何结果文件 | `true` |
| 任务名称 `task_name` | 可选 | 结果文件夹第三层的名字（也就是这批任务叫什么） | `auto-task` |
| 顶层文件夹名 `results_root_name` | 可选 | 结果根目录下的第一层文件夹名 | `results` |
| 保存位置 `results_location` | 可选 | 结果放到别的盘或共享目录时填；留空 = 用户数据目录（Windows 即便携版**外层** `EchoDesk-v0.2.2/`，不在 `app/` 里；macOS 是 `~/Library/Application Support/EchoDesk/`；Linux 是 `$XDG_DATA_HOME/EchoDesk/` 或 `~/.local/share/EchoDesk/`；三平台都可用环境变量 `ECHODESK_DATA` 改到别处） | 空（= 用户数据目录） |
| 启用定时 `schedule_enabled` | 可选 | 每天在固定时刻自动跑一轮 | `false` |
| 每天执行时刻 `schedule_times` | 可选 | 具体时刻，多个用逗号隔开 | `09:00` |
| 登录态数据目录 `login_state_dir` | 可选 | 自动化向浏览器保存登录状态用的独立目录（不与日常浏览器共用）；留空 = 程序目录下的 `browser_profile`。多个目标站点可共用一个 | 空 |
| 登录后才出现的元素 `login_check_selector` | 可选 | 判断「登录了没有」最可靠的办法：填一个只在登录后存在的元素；可用「🎯 可视化选取」点出来 | 空 |
| 登录页网址关键词 `login_url_keywords` | 可选 | 没填上一项时的兜底判断：地址里出现这些词就认为跳到登录页了 | `login, signin, sign-in, logon, sso, passport, cas, auth` |

### 2.3 只在 `app/backend/config.json` 里改的高级字段

这些字段设置窗口暂时没有对应的输入框。**改之前先关掉 EchoDesk**，改完保存、重新启动即可生效
（文件是 UTF-8，三平台上用记事本、VS Code 或任何编辑器都行——文件在各平台上的相对路径相同，
只是分隔符不同：macOS/Linux 是 `app/backend/config.json`，Windows 是 `app\backend\config.json`）。

| 配置字段 | 是否必填 | 作用 | 默认值 |
| --- | --- | --- | --- |
| `llm_temperature` | 可选 | 生成温度：越高回答越发散，越低越保守；审核类任务建议 0.2–0.4 | `0.3`（0.0–1.0） |
| `llm_max_tokens` | 可选 | 单条审核意见最长多少 token；写太长会变慢 | `512`（64–4096） |
| `wait_network_idle` | 可选 | 勾选后等页面网络请求都停下来再操作，更稳但稍慢 | `true` |
| `download_dir` | 可选 | 附件先下载到这个临时目录，处理完即清理 | 空（= 系统临时目录下 `echodesk_downloads`） |
| `processed_file` | 可选 | 处理记录的存放文件（配合「任务去重」使用） | `automation_processed.json` |
| `login_state_file` | 可选 | 登录态的**备份/迁移**文件（Cookie / localStorage）。主机制是浏览器自己的数据目录；这份 JSON 也用于从旧版本一次性导入 Cookie | `browser_state.json` |
| `manual_login_wait_seconds` | 可选 | 遇到验证码/登录时停下来等你操作，最多等这么久 | `180`（0–3600） |
| `headless` | 只读 | 自动化**只支持有头模式**（浏览器窗口可见）；写 `true` 会被强制纠正为 `false` 并打印警告 | `false` |
| `browser` | 可选 | 用哪个浏览器打开页面。取值 `auto`（默认，依次尝试 Edge → Chrome → 内置 Chromium → Firefox，用第一个能起来的）、`edge`、`chrome`、`chromium`（用程序自带的那个，无需另装）、`firefox` | `auto` |
| `browser_channel` | 可选 | **旧字段**，仅为兼容既有配置保留。当 `browser` 为 `auto` 且这里被显式设置过时，它指向的浏览器会被**提到候选最前面** | `msedge` |
| `audit_log_file` | 可选 | 审计日志文件：每个任务一行 JSON 记录 | `automation_log.jsonl` |
| `start_with_windows` | **尚未实现** | 该字段目前不会被程序读取，写 `true` 也不会开机自启；开机自启请把 `Start-EchoDesk-v0.2.2.lnk` 复制到系统「启动」文件夹（`Win+R` → `shell:startup`）。这条路径是 Windows 专属的；macOS 与 Linux 本版没有内置开机自启（自己用 `./start.sh` 启动，或接进桌面环境自带的「登录项」/自启动机制） | `false` |
| `safety_version` / `safety_accepted_at` | 只读 | 安全协议版本与你同意的时间，由程序自动记录，用于审计 | `1.0` / 空 |

### 支持哪些浏览器（以及哪些做不到）

| 类别 | 能不能用 | 说明 |
| --- | --- | --- |
| Chromium 系：**Microsoft Edge**、**Google Chrome** | ✅ 支持 | 优先使用；「复用你已经打开的浏览器」这条能力**也只对它们有效** |
| 程序自带 Chromium（`browser: chromium`） | ✅ 支持 | **不需要你另装浏览器**；两个都没装时的兜底 |
| **Mozilla Firefox**（`browser: firefox`） | ✅ 能驱动 | 但**不支持**复用你已经打开的浏览器，会另开一个窗口（也就需要重新登录一次） |
| 其它 Chromium 品牌：Brave、Opera、Vivaldi 等 | ⚠️ 本版未接 | 技术上可以支持，但需要在配置里指定它们的可执行文件路径，本版还没有这个入口 |
| **IE 内核（Trident）或自研外壳的国产浏览器**（旧版 360 安全浏览器兼容模式、QQ 浏览器 IE 模式、部分政务专用浏览器） | ❌ **做不到** | Playwright 没有 IE 内核的驱动，这类浏览器**无法**被自动化控制 |

**遇到"做不到"的那一类怎么办**：用它们把页面**另存为 / 导出成文件**，再走「本地文档」那条路
（上传文件让模型处理）；或者改用 Edge / Chrome 打开同一个系统（很多内网系统两者都能进），再用自动化。
不要指望"换一个浏览器就支持了" —— 那不是配置问题，是驱动层**根本没有这条能力**。

## 三、逐字段填写说明

> 每个字段在设置窗口里都有「?」图标，鼠标悬停即可看到同样的说明文字（内容来自语言包，会随界面语言切换）。
> 设置窗口里还有「📖 填写帮助」按钮，弹出的就是这份文档的简化版。

### 3.1 任务列表网址

- **通俗说明**：打开后能看到所有任务的页面地址。从浏览器地址栏复制粘贴即可。
- **示例**：`https://oa.example.com/task/list`
- **注意**：只支持 `http` / `https` / 文件路径（`file:`）开头的地址；写成别的协议会提示「任务列表网址协议不受支持」。
- 网址里带 `#` 或 `?` 参数没关系，原样粘贴即可。

### 3.2 任务列表元素位置

- **通俗说明**：你想让程序点击的「任务链接」在页面上的位置。点右边的「🎯 可视化选取」按钮，然后在页面上直接点一下任务名称即可。
- **如果必须手动填**：在任务链接上右键 → 检查 → 在右侧代码上右键 → 复制 → 复制选择器 → 粘贴到这里。
- **示例**：`table.task-list a.title`
- **支持两种写法**：
  - CSS 选择器（推荐）：直接写，如 `a.task-link`、`td.title > a`；
  - XPath：以 `//`、`(` 或 `xpath=` 开头，如 `//a[@class='task']`。

> 📷 屏幕上该看什么：用「🎯 可视化选取」在任务列表页点选任务名称的过程——被红色高亮框住的
> 元素、跟随鼠标的选择器预览提示条，以及顶部那条「把鼠标移到要抓取的元素上并点击；
> 按 Esc 取消」的蓝色横幅。

### 3.3 任务行容器（可选）

- **通俗说明**：如果一个任务在页面上是一整行（比如表格的一行），可以填这一行的位置，让程序更准确地定位。不确定就留空。
- **示例**：`table.task-list tr`
- **提示**：留空完全不影响使用；只有在「任务链接和别的链接混在一起、抓错了」时才需要它。

### 3.4 下一页按钮（可选）

- **通俗说明**：如果任务列表有很多页，填「下一页」按钮的位置，程序会自动翻页。只有一页就留空。
- **示例**：`a.next-page`
- **提示**：如果按钮文字是「>」「下一页 ›」「Next」，一定要选**可点击的那个元素**（通常是 `<a>` 或 `<button>`），而不是它外面包着的 `<div>`。

### 3.5 任务详情页文件元素位置

- **通俗说明**：点进任务后，能看到附件的下载链接。点「🎯 可视化选取」并选择「详情页附件」，程序会先自动进入第一个任务，然后你在附件名称上点一下即可。
- **示例**：`div.attachments a`
- **提示**：如果详情页有多个附件，选一个就能匹配到全部同类附件；测试向导第三步会告诉你匹配到几个、其中几个符合后缀要求。

### 3.6 需要预览的文件后缀

- **通俗说明**：告诉程序只处理哪些类型的文件。常用：合同用 `pdf, docx`，表格用 `xlsx`。
- **示例**：`pdf, docx`
- **可勾选**：界面上提供勾选式下拉（PDF、Word、Excel、PPT、纯文本），勾选即可，也可以直接手填。
- **容错**：写成 `PDF`、`.docx`、中文逗号「，」都没关系，程序会自动统一成小写、去掉前面的点、按逗号切开。

### 3.7 任务指令

- **通俗说明**：告诉 AI 要对文件做什么。用大白话写清楚要提取什么、要生成什么意见。
- **示例**：`提取合同金额、付款方式与期限、违约金比例、双方主体、签署日期；标注超限风险`
- **写法建议**：
  - 先说要「提取什么」，再说要「标注/判断什么」；
  - 一次说 4–6 件事就够了，写太多模型会顾此失彼；
  - 不需要写「请阅读附件」之类的客套话，程序会自动把文件内容接在指令后面。
- **预置模板**：设置窗口里可直接套用四个常用模板（见第七节）。
- **推理模型的思考内容**：如果用的是会思考的模型（Qwen3 thinking、DeepSeek-R1 等），
  自动化里"生成审核意见"这一步**只取最终答案**，思考过程不会写进任务结果、也不会进
  `result.txt`（思考内容只在与该模型的对话里显示）。这样结果文件读起来仍然是干净的结论。

### 3.8 任务名称来源（可选）

- **通俗说明**：结果文件夹用什么名字。默认用任务名称，一般不用改。
- **示例**：`合同审查`
- **实际效果**：填什么，第三层文件夹就叫什么。**同一天内重名会自动加序号**（`合同审查`、`合同审查-1`、`合同审查-2`），不会覆盖上一次的结果。
- **留空**：留空时用默认名 `auto-task`。

### 3.9 结果放在哪里

| 字段 | 通俗说明 | 示例 |
| --- | --- | --- |
| 顶层文件夹名 | 结果根目录下的第一层文件夹叫什么 | `results` |
| 保存位置 | 想把结果放到别的盘或共享目录时填这里，留空就用用户数据目录（Windows 上即便携版**外层**，也就是快捷方式所在文件夹） | `D:\合同审核结果`（Windows）· `/Users/<用户名>/Documents/合同审核结果`（macOS）· `/home/<用户名>/合同审核结果`（Linux） |

留空时，结果根目录就落在用户数据目录里，而各平台放的位置不同：

```
# Windows —— 程序目录本身（便携版就是 app/ 所在的外层目录）；
#            若就装在 %APPDATA%\EchoDesk 下，那它就是 %APPDATA%\EchoDesk
C:\Users\<用户名>\EchoDesk-v0.2.2\results\
%APPDATA%\EchoDesk\results\

# macOS
~/Library/Application Support/EchoDesk/results/

# Linux（未设置 XDG_DATA_HOME 时为 ~/.local/share/EchoDesk/results/）
$XDG_DATA_HOME/EchoDesk/results/
```

界面下方会实时预览完整目录结构，例如：
`目录结构：结果根目录 / YYYY-MM-DD / 任务名称 / result.txt + 原始文件`。
点「打开结果目录」会用系统的文件管理器打开结果根目录（Windows 是资源管理器，macOS 是访达，
Linux 是桌面环境自带的文件管理器）；点「浏览…」可以挑一个文件夹当保存位置。

### 3.10 运行参数

| 字段 | 通俗说明 | 什么时候需要改 |
| --- | --- | --- |
| 最多任务数 | 一轮最多处理几个任务 | 想先小范围试水时填 `5` |
| 页面超时(ms) | 打开网页最多等多久 | 内网系统慢、经常超时，调到 `60000` |
| 重试次数 | 某个任务失败后自动重试几次 | 网络不稳时填 `2` |
| 任务去重 | 处理过的任务下次自动跳过 | 想重新处理全部任务时取消勾选 |
| 保存结果到本地文件 | 不勾选就只做试运行，不写结果文件 | 只想看流程时取消勾选 |

### 3.11 定时触发

- **通俗说明**：打开「启用定时」后，填每天什么时候自动跑一轮，多个时间用逗号隔开，例如 `09:00, 18:30`。
- **注意**：定时任务由程序后台线程调度，**要求 EchoDesk 保持运行**；时间格式非法（如 `25:00`）会被自动剔除。
- 想开机自动启动，只能把「Start-EchoDesk-v0.2.2.lnk」放进系统「启动」文件夹（`Win+R` → 输入 `shell:startup`）。
  **配置项 `start_with_windows` 尚未实现**：程序不会读取它，改成 `true` 也没有效果。
- 这条快捷方式路径**从名字到机制都是 Windows 专属**（`.lnk` 文件 + `shell:startup` 文件夹）。
  macOS 与 Linux 本版没有内置开机自启：自己用 `./start.sh` 启动，或把启动命令接进桌面环境自己的机制
  （macOS 的「登录项」、Linux 桌面环境的自启动项或 systemd 用户单元）。

### 3.12 安全协议与自动化总开关

- 界面上先出现的是安全协议：勾选「我已阅读并理解上述安全协议，自愿承担使用责任」；
- 未勾选时，总开关会被后端**强制关闭**，并在日志里提示；
- 协议版本与你同意的时间会写进审计日志，便于事后追溯。

### 3.13 登录态相关字段（数据目录 / 登录检测元素 / 登录页关键词）

这三个字段都在**设置窗口 → 自动化 → 登录态**里，绝大多数用户**不用改**（默认值就能用）。
它们的完整说明、以及「未登录时程序会怎么做」「怎么清除登录态」「多站点怎么共用」见**第十节**。
一句话版：

- **数据目录**：自动化单独保存登录状态的目录，第一次登录一次，之后自动复用；留空即可；
- **登录后才出现的元素**：想让它更聪明地判断"登录了没有"就填它（例如右上角用户名），
  用「🎯 可视化选取」点一下就能填上；
- **登录页网址关键词**：没填上面那项时的兜底判据，一般不用动。

### 4.3 跑完之后的结果目录长什么样

保存位置留空时，结果就在**用户数据目录**里——Windows 上是外层 `EchoDesk-v0.2.2/`

```
<用户数据目录>/
└── results/                      ← 顶层文件夹名（可自定义）

            ├── 年度采购合同.pdf          ← 下载下来的原始附件（重名自动加序号）

```

`result.txt` 是**纯文本**（文本编辑器能直接看，没有 `#`、`**`、`|` 这类符号），内容大致是：

## 五、测试选择器的正确流程

**先测再跑**是这套功能最重要的使用习惯。点「测试选择器」会进入一个分步向导，
每一步都明确告诉你成功了还是失败了、下一步该做什么。

### 第 1 步：测试任务列表元素位置

- 程序打开浏览器访问任务列表页，按你填的位置高亮匹配到的元素；
- **成功的样子**：显示匹配数量与前几个任务的名称（例如「匹配到 8 个任务链接，例如：年度采购合同、服务协议、设备采购单」）；
  如果你还填了「任务行容器」，会额外告诉你匹配到多少行；**这一步通过后就可以先不管行容器**。
- **失败的样子与处理**：
  - 「页面已打开，但这个选择器没有匹配到任何元素」→ 确认这一页确实显示了任务列表（有些系统要先登录）、用「🎯 可视化选取」重新点一次任务名称、列表在分页或懒加载里时先滚动到任务出现再选；
  - 「测试失败：…」→ 检查网址能否在浏览器里正常打开、选择器是否被误改。

### 第 2 步：测试下一页按钮

- 程序会**真的点一下**「下一页」，然后报告页面有没有跳转。
- **成功的样子**：「找到并点击了「下一页」按钮，页面已跳转。点击后地址：…」。
- **失败的样子与处理**：
  - 「没有配置「下一页按钮」」→ 单页列表的正常情况，这一步会直接通过，可以继续；
  - 页面未跳转 → 如果你点的时候这页确实是最后一页，未跳转是正常的；否则可能是按钮由脚本处理，换一个更精确的选择器，或选里面真正可点的那个元素。

### 第 3 步：测试任务详情页文件元素位置

- 向导会**先自动进入第一个任务**，再在详情页里测试附件位置；
- **成功的样子**：「在任务『年度采购合同』的详情页里匹配到 3 个附件元素，其中 2 个的后缀在「需要预览的文件后缀」内。」
- **失败的样子与处理**：
  - 「在任务详情页里没有匹配到附件元素」→ 用「🎯 可视化选取」选择「详情页附件」重新点一次；确认第一个任务确实带附件；
  - 「其中 0 个的后缀在…内」→ 附件格式不在你填的后缀里，按提示把缺少的后缀补上（例如补 `ofd`）；
  - 「任务列表选择器没有匹配到可用任务」→ 先回头把第 1 步做通过。

### 第 4 步：试运行一个任务（不写结果文件）

- 只处理第一个任务，完整走一遍下载与解析，并告诉你模型生成的审核意见，
  **但不会写任何结果文件**（相当于 `save_results` 关闭状态下的演练）。
- **成功的样子**：日志里依次出现「进入详情 → 下载 → 解析 → 正在生成审核意见 →」以及生成出来的意见文本；
  通过后向导会提示：确认无误就可以勾选安全协议、打开总开关，正式批量处理了。
- **失败的样子与处理**：
  - 「配置还没通过校验：- …」→ 按列出的每一条补齐配置（例如还没勾安全协议、还没开总开关、没加载模型）；
  - 报错指向下载或登录 → 按提示检查选择器与登录状态，并确认这台电脑上能用手动方式完成同样的下载。

### 第 5 步：确认安全协议并开启自动化

- 向导走完后，回到安全协议区，勾选「我已阅读并理解上述安全协议，自愿承担使用责任」；
- 然后打开「启用自动化功能」开关（未勾选协议时这个开关点不动，或会被自动关回去）；
- 最后点「▶ 立即运行一次」，建议**第一轮把「最多任务数」调成 3–5**，看清楚了再放大。

> 📷 屏幕上该看什么：「测试选择器」向导第 1 步成功时的界面——绿色的成功提示、匹配数量、
> 样例任务名称，以及「下一步」按钮。

## 六、常见错误与排查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 测试选择器提示「没有匹配到任何元素」 | 选择器写错了；或页面还没加载完；或这一页本来就没有任务 | 用「🎯 可视化选取」重新点一次任务名称；确认这一页能看到任务列表；稍等几秒再测 |
| 匹配到的元素特别多（几十上百个），下载时抓到一堆无关链接 | 选择器选得太宽（例如选到了整个 `<ul>` 或所有 `<a>`） | 改成只指向「任务名称」的那个链接元素，例如 `table.task-list a.title`；必要时再填「任务行容器」限定范围 |
| 页面一打开是登录页 / 提示未登录 | 登录态不存在或已过期 | 第一次运行时会弹出浏览器窗口，请手动登录一次；登录态会存进 `browser_state.json` 供下次复用 |
| 之前能用，忽然又要重新登录 | 登录态过期，或网站更换了 Cookie/域名；也可能是删除了 `browser_state.json` | 重新手动登录一次；若频繁过期，检查公司是否有会话时长限制 |
| 「没有匹配到「下一页」按钮」 | 选择器指向了外层容器，或按钮文字是图标；或这页是最后一页 | 用「🎯 可视化选取」在列表页底部点一下「下一页」；换成里面真正可点击的元素 |
| 附件下载超时 / 一直卡在下载 | 内网慢、文件大，或下载走的是新的浏览器标签页 | 把「页面超时(ms)」调大到 `60000`；确认手动点击该附件能正常下载；必要时把「重试次数」设为 `2` |
| 「详情页没有符合后缀要求的文件链接」 | 附件的扩展名不在「需要预览的文件后缀」里 | 把实际后缀补进该字段（如 `ofd`、`wps`）；用向导第 3 步确认附件确实被匹配到 |
| 附件下载了但解析结果为空 | 扫描件 PDF 没有文本层，或文件损坏 | 扫描件需要 OCR（本版未内置），先用 WPS/Office 另存为可复制文本的格式；也可把该任务单独手动处理 |
| 解析 `.doc` / `.ppt` 报错或提示需要 WPS | 旧版二进制格式（及加密文档）通过 COM 读取，本机没装 WPS/Office | 安装 WPS 或 Microsoft Office；或先把文件另存为 `.docx` / `.pptx` 再上传。COM 这条路径和这条建议都是 **Windows 专属**；非 Windows 上该能力会作为"平台不提供"报出（而不是"依赖缺失"）——替代做法见本文开头的提醒 |
| 模型太慢，或提示「模型返回为空」 | 「任务指令」太长、`llm_max_tokens` 太大，或附件内容过长触发分段摘要 | 把任务指令压到 4–6 个要点；把 `llm_max_tokens` 调到 384–512；换更小的量化模型（如 Q4_K_M） |
| 结果目录没有生成 / 提示无法写入 | 「保存位置」填了一个不存在或没有写权限的路径（网络盘、系统受保护目录） | 把「保存位置」留空用用户数据目录（各平台位置见 3.9），或改成本机可写目录（Windows 如 `D:\合同审核结果`，macOS 如 `/Users/<用户名>/Documents/合同审核结果`，Linux 如 `/home/<用户名>/合同审核结果`）；确认磁盘未满 |
| 到了定时时间没有自动跑 | 程序没有在运行（定时由程序后台线程调度）；或时间格式非法被剔除；或没打开「启用定时」 | 保持 EchoDesk 运行；Windows 上把「Start-EchoDesk-v0.2.2.lnk」放进 `shell:startup` 实现开机自启（macOS/Linux 需用桌面环境自带的「登录项」/自启动机制，本版没有内置）；时间写成 `09:00` 这种两位小时格式 |
| 想看某个任务到底做了什么（审计追溯） | 需要事后核对谁在什么时候处理了哪些文件 | 打开审计日志 `app/backend/automation_log.jsonl`，每个任务一行 JSON 记录（见第九节） |
| 提示「未加载本地模型，无法生成摘要与审核意见」 | 还没选好/下载好本地模型 | 先在主窗口用 `/model list` 与 `/model 文件名` 选好模型 |
| 提示「未安装 playwright，请先执行 pip install playwright」 | 源码方式运行且缺少依赖（打包版自带） | 源码运行请执行 `pip install -r backend/requirements.txt` 后重启（macOS/Linux 上 `python`/`pip` 不在 PATH 时用 `python3 -m pip install -r backend/requirements.txt`；路径分隔符在那些平台是 `/`，Windows 是 `\`） |

## 七、预置模板

设置窗口里提供四个模板，点一下就把「任务指令」和「需要预览的文件后缀」填好，再按自己的网站微调即可。
模板内容走语言包，界面语言切换后模板文字也跟着变。

| 模板名 | 任务指令要点 | 常用后缀 |
| --- | --- | --- |
| 合同财务审核 | 提取合同金额、付款方式与期限、违约金比例、双方主体、签署日期；标注超限风险 | `pdf, docx` |
| 发票信息提取 | 提取发票号、开票日期、金额、税额、购买方、销售方、商品明细 | `pdf, ofd` |
| 报告要点汇总 | 汇总核心结论、关键数据、建议事项 | `pdf, docx, pptx` |
| 表格数据核对 | 核对金额与合计是否一致，标注异常行 | `xlsx, xls` |

**保存自己的模板**：把「任务指令」和「需要预览的文件后缀」按你的业务写好之后，
用「保存为自定义模板」把当前配置存下来，给它起个名字（例如「月结单核对」）；
下次在模板列表里点一下就能套用（提示「✅ 已套用模板「月结单核对」」）。

**模板 vs 配置导出**：模板只保存「任务指令 + 后缀」这类可复用的文字；
要把整套配置（网址、选择器、结果位置……）搬到另一台电脑，用第八节的导出功能。

## 八、配置导出与导入（`.echodesk-auto`）

### 8.1 导出

- 导出的文件扩展名是 `.echodesk-auto`（内部是 JSON，可以直接用文本编辑器查看）；
- 默认导出到桌面，文件名形如 `echodesk-automation.echodesk-auto`；
- 文件里包含：格式标记（`format: echodesk-automation`）、结构版本、EchoDesk 版本、导出时间、
  导出时的界面语言，以及整套 `automation` 配置；
- **不会包含**：登录态（`browser_state.json` 里的 Cookie）、处理记录（`processed_file`）、
  下载临时目录（`download_dir`）——这几项既敏感又与具体机器绑定，导出时被排除。
  也就是说，**文件里没有任何 Cookie 或 Token，可以安全地在同组织的电脑之间传递**。

### 8.2 导入

- 导入时只会应用当前版本认识的字段，其余忽略；
- **出于安全考虑，安全协议与自动化总开关不会被导入**：导入后需要你在本机重新勾选协议、
  再打开总开关才能运行（提示：出于安全考虑，导入时不会继承「安全协议」与「自动化总开关」，请在本机重新勾选后再运行。）；
- 如果这份配置是在**另一种界面语言**下填写的，程序会提示一句（例如
  「提示：这份配置是在「en」环境下填写的，当前界面语言是「zh-Hans」，字段内容会原样导入，请自行确认选择器与指令是否需要调整。」），
  但**不会阻断导入**——选择器和指令都是你自己写的内容，本来就保持原样。

## 九、安全与审计

- **安全协议是前置条件**：只有勾选「我已阅读并理解上述安全协议，自愿承担使用责任」之后，
  自动化总开关才可能生效；否则后端会强制把它关回去，并记录提示。
- **全程可见**：自动化**只使用有头模式**（浏览器窗口始终可见），不使用无头静默运行；
  遇到验证码或二次验证会暂停等你手动处理，超时则停止本轮。
- **审计日志**：默认写 `app/backend/automation_log.jsonl`，**每个任务一行 JSON 记录**，字段包括
  时间、事件类型（`run_start` / `task` / `run_end` / `manual_required`）、任务链接、
  **仅文件名**（不含文件内容）、结果（`ok` / `failed` / `skipped`）、失败原因（截断）、
  以及安全协议版本与同意时间。日志中的 Token、密码等值会自动脱敏；
  文件正文、模型输出、Cookie 一律不写入。
- **结果落盘位置**：结果只写到你配置的结果根目录（`结果根目录/日期/任务名称/`），
  原始附件、`result.txt`、失败截图都留在该目录内；下载过程中的临时副本处理完即清理。
  不填「保存位置」时，结果根目录就是**用户数据目录**——Windows 上是 `app/` 旁边那个外层
  `EchoDesk-v0.2.2/`，macOS 上是 `~/Library/Application Support/EchoDesk/`，
  Linux 上是 `$XDG_DATA_HOME/EchoDesk/` 或 `~/.local/share/EchoDesk/`（见 3.9）；
  想让用户数据整体换位置（含 `ui_state.json`、`snippets.json`、`results/`），
  可在启动前设置环境变量 `ECHODESK_DATA`。
- **去重记录**：`processed_file`（默认 `automation_processed.json`）里只保存任务链接的哈希，
  用于下次跳过已处理的任务，不含网页内容。

## 十、登录态：登录一次，之后自动复用

每次运行都重新登录一遍，对非技术用户来说等于不可用。所以自动化**单独用一个浏览器数据目录**
把你的登录状态存起来，下一次运行直接接着用。

### 10.1 程序是怎么做的

| 环节 | 程序的行为 | 你要做什么 |
| --- | --- | --- |
| 数据目录 | 自动化专用，默认是 `browser_profile`（与 `browser_state.json` 同级）；可在「登录态 → 数据目录」里改，或改 `login_state_dir` | 一般不用管 |
| 首次运行 | 有头打开浏览器、打开任务列表页；判定为未登录时会**暂停**并在下方提示你手动登录 | 在弹出的浏览器窗口里正常登录一次 |
| 登录成功后 | 浏览器自动把 Cookie / localStorage 写进数据目录，程序检测到已登录后**自动继续**，不需要重启 | 什么都不用做 |
| 之后的运行 | 直接复用数据目录里的登录状态，**不会再要求登录** | 什么都不用做 |
| 登录过期 | 又会被判为未登录，于是再次暂停等你登录一次 | 重新登录一次 |

数据目录**不与你的日常浏览器共用**：浏览器不允许两个实例同时使用同一个 user data dir，
共用会直接启动失败，因此自动化必须有自己的那一份。

### 10.2 程序怎么判断「登录了没有」

按可靠性从高到低：

1. **登录后才出现的元素**（`login_check_selector`）——最可靠。填一个只在你登录后才存在的元素
   （例如右上角的用户名），程序找不到它就认为没登录。点右边的「🎯 可视化选取」可以直接在页面上点出来。
   注意：**要挑登录后才出现的元素**，不要挑登录页上也有、登录后也在的元素（比如页面框架、页脚）。
2. **登录页网址关键词**（`login_url_keywords`，默认 `login, signin, sign-in, logon, sso, passport, cas, auth`）
   —— 兜底判断：当前地址里出现这些词，就认为被跳到登录页了。
3. 两者都没有信息时，程序**不猜测、不打扰你**，只往审计日志里写一条"无法判断"。

### 10.3 检测到未登录时，程序会怎么做

- 暂停并提示：`检测到当前未登录：请在浏览器窗口里手动登录，程序将等待最多 N 秒…`
  （首次使用时提示语会说明"首次使用需要你手动登录"）；
- 你在浏览器里登录成功后，程序检测到已登录，提示 `已检测到登录成功，继续执行。` 后自动往下跑；
- 如果等满 `manual_login_wait_seconds`（默认 180 秒）还没登录，程序会明确报
  `未检测到登录状态（已等待 N 秒），本轮不再继续` 并结束本轮——**不会**让每个任务各失败一遍。
  这一点是刻意的：没登录的话后面每个任务都会失败，跑完再报一堆失败对你没有任何帮助。

### 10.4 清除登录态

设置窗口 →「登录态」→「🗑 清除自动化登录态」：删除数据目录（以及旧的 `browser_state.json` 备份），
下次运行重新引导你登录一次。

- 自动化正在运行时不能清除（会提示你先停止）——浏览器正占着这些文件；
- 不会影响你日常使用的浏览器，也不会删除任何结果文件；
- 想换一个登录账号时，也走这一步。

### 10.5 多个目标站点怎么办

**可以共用一个数据目录**：浏览器按域名分别保存 Cookie，A 站点的登录态不会串到 B 站点，
不需要为每个站点单独配一份。

### 10.6 隐私与审计

- 数据目录与 `browser_state.json` 备份都**只在本机**，程序不会上传它们；
- `browser_state.json` 仍然会导出（也用于从旧版本一次性导入 Cookie，老用户升级后不用重新登录），
  方便你备份或换机迁移；
- 审计日志只记录**事件**：`login_state_used`（复用了登录态）、`login_required`（暂停等你登录）、
  `login_completed`、`login_timeout`、`login_state_cleared`（清除）、`login_state_migrated`（导入）。
  事件里只有路径、结果与计数，**不写任何 Cookie 内容**。

### 10.7 高级选项（本版未实现）

用 CDP 连接一个已经以调试模式启动的浏览器（`connect_over_cdp`）：好处是直接用你日常的浏览器实例、
登录态天然存在；代价是每次都要你手动以调试模式启动浏览器。本版**没有实现**，仅在此说明。

## 十一、程序怎么从元素里拿到网址（href 提取）

### 11.1 先纠正一个常见误解

「任务列表元素位置」「任务详情页文件元素位置」填的是**选择器**，它的职责只有一件事：
**找到元素**。它不负责读属性。正确的流程是四步：

1. **定位** —— 用选择器找到 `<a>` 元素；
2. **读取属性** —— 对这个元素读 `href`（程序还会依次尝试 `data-href` / `data-url`，
   兼容用 `<div data-href="...">` 承载地址的站点）；
3. **规范化** —— 相对路径（如 `detail.html?id=1`）拼上当前页面的 origin，变成绝对地址；
4. **特殊情况回退** —— 伪链接不能用来导航，改为**点击元素**触发跳转。

### 11.2 五种 href 的处理方式

| 页面上的写法 | 程序怎么处理 |
| --- | --- |
| 相对路径 `href="detail.html?id=1"` | 补全为绝对地址后直接打开 |
| 绝对地址 `href="https://…/detail.html?id=2"` | 原样打开 |
| `href="javascript:void(0)"` | 提取不到网址 → **改为点击这个元素**触发跳转 |
| `href="#"`（或 `#section`） | 页内锚点不是任务/附件地址 → **改为点击** |
| 没有 `href` 属性 | **改为点击** |

也就是说：**伪链接不会让程序失败**，它会自动换成点击。点击之后无论目标页面是在当前标签页打开、
还是在新标签页打开，程序都能接住并继续。每一类在处理时都会在界面上写明原因，例如
`这个元素没有可直接打开的网址（javascript:void(0)），改为点击它来跳转…`。

### 11.3 可视化选取会告诉你选中的是什么

点「🎯 可视化选取」在页面上点一下元素之后，程序不会只丢给你一个选择器字符串，而是：

1. **先预览**：弹窗里列出「程序将从这些元素提取以下网址：…」，让你确认位置选对了才写入配置
   （点「取消」就放弃这次选取，配置不变）；
2. **非链接元素识别**：如果你点到的是按钮、`<div>` 这类读不到网址的元素，会明确提示
   `你选中的不是链接（<button>），无法提取网址，请重新选择。`，**并且不会把配置写坏**；
   如果点到的容器里还有链接，提示会进一步说明
   `你选中的是容器 <div>（里面还有 N 个链接）…请改点容器里的具体链接元素。`；
3. **伪链接提示**：如果选中的是 JavaScript 伪链接或空 href，预览里会说明
   `提取不到网址（JavaScript 伪链接），程序会改为点击元素触发跳转`；
4. **只匹配到 1 个元素时提醒**：可视化选取生成的是"精确到这一个元素"的选择器。如果这个位置本该有
   多条（任务列表里有多个任务、详情页有多个附件），预览会提醒你把选择器改通用一些
   （例如把 `li:nth-of-type(1) > a.task` 改成 `a.task`），或在「任务行容器」里选一整行。

### 11.4 四个选取位置各自代表什么

| 选取位置 | 程序拿它做什么 | 是不是必须是链接 |
| --- | --- | --- |
| 任务列表元素位置 | 读 `href` 作为**跳转目标**，逐个进入任务 | 是（伪链接会自动改成点击） |
| 任务行容器（可选） | 先定位一整行，再在**行内**查找任务链接 | 否，它本来就是容器 |
| 下一页按钮（可选） | 只**点击**它来翻页，不读网址 | 否，按钮不是链接 |
| 任务详情页文件元素位置 | 读 `href` 用来**下载**附件 | 是（伪链接会自动改成点击） |

「你选中的不是链接」这条拦截只对**必须是链接**的两个位置生效；选「任务行容器」或「下一页按钮」时，
选中容器或按钮是正常的。
