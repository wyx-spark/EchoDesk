## 一、安装与启动

### 安装版（推荐）
1. 双击 `EchoDesk-v0.2.2-Setup.exe`（只有这一份安装程序，**不含内置模型**，首次启动会询问是否下载）。
   不需要管理员权限。
2. **默认装到"安装程序自己所在的文件夹"** —— 把安装程序放进 `D:\Tools\EchoDesk\` 再双击，
   就装到 `D:\Tools\EchoDesk\`。向导里有路径选择页，想装到别处在那里改即可。
3. 向导会创建开始菜单快捷方式（勾选后也创建桌面快捷方式），最后询问是否立即启动。
   之后要卸载，走系统「应用和功能」（或开始菜单里的卸载项）。

装出来的目录结构与便携版**完全一致**：程序本体在 `app\`，你的数据与 `results\` 就在安装目录里。

### 便携版（zip 免安装）
1. 把整个 `EchoDesk-v0.2.2` 文件夹解压到任意位置（桌面、D 盘、U 盘均可）——
   不会往该文件夹以外写任何东西，删除文件夹即卸载；
2. 双击文件夹内的**「Start-EchoDesk-v0.2.2.lnk」**——这是唯一入口，
   不需要分辨 `app\EchoDesk.exe` 与 `app\backend\EchoDeskBackend.exe` 的区别
   （后者由界面自动拉起，请勿单独运行）。
   zip 里没有预置快捷方式（快捷方式记的是绝对路径，在别人机器上生成的必然是死链）——请先运行一次
   `install-complete.bat`，或直接双击 `app\EchoDesk.exe` 并接受"创建快捷方式"的询问；
3. 首次启动会依次处理三件事：
   - 若 `app\backend\models\` 里没有模型 → 询问是否下载（约 472MB，需联网）；
   - 若文件夹内没有快捷方式 → 询问是否创建；
   - 显示一次上手引导。

**两层结构**：外层（`EchoDesk-v0.2.2\`）只放快捷方式、用户数据与文档，**程序本体全部在 `app\` 里**
——外层不出现任何 exe/dll，要卸载时删掉整个文件夹即可。

### 目录结构与你需要知道的位置

下表里的路径都相对便携版**外层**目录（`EchoDesk-v0.2.2\`）。**`app\` 里是程序本体，不要往里放自己的东西；
外层才是你的数据目录**，备份与清理都以外层为准。

| 位置 | 内容 | 能不能删 |
| --- | --- | --- |
| `app\backend\config.json` | 全部配置（模型、窗口、摘要、**本地检索**、**Agent 工具权限**、**MCP**、自动化、市场） | 可删（会重建为默认值） |
| `app\backend\models\*.gguf` | 本地模型 | 可删（下次启动会询问重新下载） |
| `app\backend\session.json` | 上次对话（自动恢复） | 可删（清空历史） |
| `app\backend\browser_state.json` | 自动化的登录态（Cookie） | 可删（退出所有登录） |
| `app\backend\automation_log.jsonl` | 自动化审计日志 | 可删（建议先归档） |
| `app\backend\skills\` + `app\backend\skills_registry.json` | 已安装技能 | 建议用市场卸载 |
| `app\backend\summary_cache.json` | 长文档分段摘要缓存（可读 JSON） | 可删（下次上传重新计算） |
| `results\` | 自动化结果（按 `日期\任务名\` 分层） | 可删（建议先归档） |
| `lang\` + `app\lang\ui\` | 后端 / 界面语言包（可自行新增语言） | 不建议删（删掉会退回内置文案） |
| `ui_state.json` | 窗口位置/大小、字号、主题 | 可删（重置界面状态） |
| `snippets.json` | 常用语 | 可删 |
| `USAGE.txt` | 面向用户的结构说明 | 可删 |

**备份**：需要保留对话记录与设置时，复制 `app\backend\session.json`、
`app\backend\config.json`、`snippets.json` 三个文件即可。

**数据位置**：`ui_state.json`、`snippets.json` 与 `results\` 都在便携版**外层**目录（不在 `app\` 里）。
想让它们落到别的位置（例如 U 盘或用户目录），可以在启动前设置环境变量 `ECHODESK_DATA`
指向目标目录，程序会把用户数据写到那里。

### 没有模型也能启动

EchoDesk 不自带模型权重。本地没有模型时程序**照样启动并保持可用**——不退出、不卡住、
也不会在未经你操作前下载任何东西：

1. 状态栏显示**「无模型」**，对话框给出引导并附上模型文件夹的真实路径。
2. 不依赖推理的功能照常可用：文件解析、设置、技能市场、模型市场、会话历史；
   提问会返回引导而不是报错。
3. 四种拿到模型的方式，**都不需要重启程序**：
   * **设置 → 模型 → 模型档位** → 已登记的档位（默认是小档 `Qwen3-0.6B-Q6_K`）点一下胶囊即可**切换**；
     还没下载的档位点一下会**先在它自己的仓库里找到并下载**，下完即可切换。
   * **设置 → 模型 → 模型市场** → 搜索并下载。见下一节「模型市场怎么用」。
   * 把 `.gguf` 文件放进 `app\backend\models\`，点**「重新扫描模型文件夹」**；
     只扫描到一个模型时会自动加载。
   * 在「本地模型库」里点已下载模型旁的**「加载」**。
4. 模型加载成功后，状态栏从"无模型"变为模型名，立刻可以对话；加载失败会给出原因并可重试，
   两种情况程序都在继续运行。

### 模型市场怎么用

在**设置 → 模型**页里，搜索框输入关键词后回车（或点「🔍 搜索」）即可。

* **一次取回全部结果**：程序会自己按页把该关键词的全部结果取回来（不再只显示 20 条），
  过程有进度提示"已加载 N 条"；嫌久可以点「⏹ 停止」，已经取回的部分会保留。
* **取不完也不会失控**：单次加载有条数 / 请求次数 / 耗时三个上限，达到上限时明确告诉你
  "已加载 N 条，还有更多"，并出现「⤵ 继续加载」按钮接着取。
* **结果会缓存**：同一关键词第二次搜索直接用本地缓存（秒开）。想强制刷新点「↻ 刷新」。
* **分页控件固定在列表下方**，滚动结果列表时它不会跟着滚走：⏮ 首页 / ◀ 上一页 /
  下一页 ▶ / 末页 ⏭ / 跳至第 N 页（回车生效，输入非法会给提示）/ 每页 20、50、100 条可切换。
* **本地筛选**：在筛选面板里输入词，会在**已经取回的结果**里实时过滤（仓库名 / 描述 / 标签），
  **不会重新联网**；同时可以按参数量、量化格式、更新时间、是否已下载、是否推荐做多选筛选
  （同一个维度内多选是"或"，不同维度之间是"且"）。筛选与翻页条件在切页时保持不变。
* **三层数字看得清**：状态行显示「本地筛选后 A 条 / 已加载 B 条 / 共 C 条」。
  本地筛完没有结果时，会出现「重新搜索远端」的入口，而不是让你以为是网络坏了。
* **排序**：按历史总下载量 / 点赞最多 / 最近更新 / 参数量。切换排序会按该维度重新取回结果。
* **下载量口径**：列表里显示的是**历史总下载量**，与 Hugging Face 网页上默认展示的
  「最近 30 天下载量」**不是一个数**，比较时请以上面的口径说明为准。个别条目若接口没有
  历史总量字段，会回退为「最近 30 天」并逐条标注，不会显示成 0。
* **默认模型钉在最上方**：`config.json` 里配置的模型所在仓库固定显示在结果列表上方，
  标着来源，且**不计入下方的分页条数**。
* **离线时**：远端不可达会在状态行标出「📴 离线模式」，并展示上次缓存的结果与本地已下载的模型。

### 长文档正在分段摘要时

长文档会分段摘要。对话框会实时显示进度，而不是沉默：当前阶段、正在处理第几段共几段、
已耗时、当前段已生成多少文字。只是**偏慢**的段会被标注为偏慢并继续跑；
点停止会立刻中止，原文保留在上下文中（不会注入半份摘要），随时可以用 `/summarize` 重来。

### 会思考的模型：思考过程与答案分开展示

如果你用的是**推理模型**（Qwen3 的 thinking 模式、DeepSeek-R1 系列等），模型会先"想"
再答。EchoDesk 把这两部分分开显示：

* 答案区**只放最终答案**，不会再把 `<think>…</think>` 之类的思考标签和答案混在一起；
* 答案上方有一个**「🧠 思考过程」**折叠区，默认收起，点标题栏就能展开/收起；
* 流式生成时思考区会**先自动展开**（让你看得见模型在想什么），**答案一开始输出就自动收起**；
  你自己手动展开过的话，不会强行再收起；
* 模型这次没有思考内容时，界面上**不会出现空的折叠区**。

思考区的两条实际规则，值得知道：

1. **思考内容不会作为上下文发给模型**。它只用于展示与历史回放。这既省上下文窗口
   （思考往往比答案还长），也符合推理模型本身的用法——DeepSeek-R1 的模型模板自己就
   只接受 `</think>` 之后的答案。
2. **思考内容会随对话一起保存**，重新打开 EchoDesk 恢复上次会话时，思考区还在
   （默认收起）。想让它不保存，见 `config.json` 的 `reasoning.persist`。

两条相关的小提示：

* 复制按钮（📋 / ⧉ / </> 与 `Ctrl+Shift+C`）**只复制答案**，不会把思考内容一起带走；
  真要复制思考内容，可以在展开的思考区里拖选，或从 `/save` 导出的对话记录里取
  （导出件里思考是可折叠块）。
* 如果模型"想太多、来不及答"，界面会在答案区提示**模型只输出了思考内容**。
  这通常是生成长度上限用完了：用 `/preset quality` 切到高质量档（生成长度 2048），
  或在 `config.json` 里调大 `max_tokens`（默认 1024），也可以把问题问得更具体。

### 在 Linux 或 macOS 上运行

正式交付物是 Windows 版；Linux 与 macOS 由跨平台前端（Avalonia）支持，后端是同一份
Python 代码。**绝大多数功能三平台一致**（对话与流式输出、文件解析、本地检索、Agent、
MCP、插件、模型管理与本地推理），只有两项能力是 Windows 专属：

* **读取 WPS/Office 加密文档**（以及旧版 `.doc`/`.xls`）：需要 WPS 的 COM 接口，
  非 Windows 平台没有这个机制。此时界面会明确说明"该能力仅 Windows 提供"，
  并给出替代做法（在 Windows 上用 WPS 另存为未加密文件或 `.docx` 后再读、
  通过 MCP/插件接入外部转换工具、或安装提供该格式解析器的技能）。
  **不会**把这种情况显示成笼统的"解析失败"，也不会让你去装一个装了也没用的组件。
* **企业内网自动化**（驱动本机 Edge）：该页面在非 Windows 上不提供，
  配置校验会说明原因是"平台不支持"而不是"依赖没装"。
  替代做法是用 MCP/技能调用外部脚本，或在一台 Windows 机器上跑完再把结果拿过来。

其他与平台有关的差异：

* **数据目录**：Windows 用发布物外层目录（或 `ECHODESK_DATA` 指定的位置）；
  macOS 用 `~/Library/Application Support/EchoDesk`；
  Linux 用 `$XDG_DATA_HOME/EchoDesk` 或 `~/.local/share/EchoDesk`。
* **界面语言包**放在 `<数据目录>/lang/ui/`；`ECHODESK_LANG_DIR` 可以临时指定另一个目录。
* 界面顶部的平台横幅只在**有降级项**时出现，点右上角的 ℹ️ 可以看到本平台的完整能力清单。

完整的平台矩阵、打包方式与验证证据见 `docs/zh-Hans/CROSS_PLATFORM.md`。

#### 在 Linux / macOS 上安装与启动

Linux 与 macOS 的发布物是**免安装的压缩包**（自包含：连着界面运行时和后端解释器一起打包，
目标机器不需要预装 .NET 或 Python）：

| 平台 | 下载的文件 | 解压后怎么启动 |
| --- | --- | --- |
| Linux x86-64 | `EchoDesk-<版本>-linux-x64.tar.gz` | `./start.sh` |
| macOS（Apple 芯片） | `EchoDesk-<版本>-osx-arm64.tar.gz` | `./start.sh` |

四步：

1. **下载并校验**。`SHA256SUMS.txt` 与压缩包在同一处；校验一下能确认下载过程没有损坏：
   Linux 用 `sha256sum -c SHA256SUMS.txt`，macOS 用 `shasum -a 256 -c SHA256SUMS.txt`。
2. **解压**：`tar -xzf EchoDesk-<版本>-linux-x64.tar.gz`，得到一个
   `EchoDesk-<版本>-linux-x64/` 目录（下面叫"发布目录"）。
3. **启动**：`cd` 进发布目录后执行 `./start.sh`。若权限位在解压时丢了，
   先执行一次 `chmod +x start.sh app/EchoDesk`。脚本本身只做一件事：
   把 `app/EchoDesk` 接管过去，因此你在终端里按 Ctrl-C 或关窗口都能正常结束它。
4. **首次启动会稍慢**（十几秒）：界面要拉起后端、后端要初始化。看到顶部状态从
   "正在连接后端"变成"就绪"或"后端已就绪，但没有加载模型"就说明起来了。

发布目录里有什么：

* `start.sh` —— 启动入口（等价于直接跑 `app/EchoDesk`）；
* `app/` —— 程序本体，`app/backend/` 是自带解释器的后端；
  `app/backend/run-backend.sh` 可以**单独手动启动后端**，用于排障
  （日常使用不必手动跑，界面会自己拉起它，并在窗口关闭时收干净）；
* `docs/`、`README*.md`、`EULA*.md` 等 —— 文档与许可证；
* 用户数据（对话记录、设置、语言包、常用语）**不在这里**，按上一节的平台惯例存放。

两个平台各自可能遇到的拦路问题：

* **macOS 的 Gatekeeper**：当前发布物**未做代码签名与公证**（需要维护者的 Apple 开发者证书
  与账号）。首次打开可能被系统拦下。两种做法都行：在访达里右键点 `app/EchoDesk`
  选「打开」并确认；或者在终端执行 `xattr -dr com.apple.quarantine app/EchoDesk`。
  发布目录里的 `SIGNING.txt` 写明了这一步还差什么、维护者需要哪条命令。
* **Linux 上没有图形环境**：界面是 GUI 程序，需要 X11 或 Wayland。纯服务器上想验证后端能不能跑，
  用 `app/backend/run-backend.sh` 手动启动，按 JSON 行协议与它交互
  （每行一个 JSON 请求，响应也是一行一个 JSON）。

## 二、日常问答

1. 在下方输入框输入问题，`Ctrl+Enter` 发送（`Enter` 是换行）；
2. 生成中想打断：按 `Esc` 或点 ⏹；
3. 想复制某段回答：用该条消息右下角的按钮——
   - 「📋 复制」→ 纯文本；
   - 「⧉ Markdown」→ 保留原始标记（粘到支持 Markdown 的地方会重新排版）；
   - 「</> 代码」→ 只复制代码块；
   - 也可以直接用鼠标拖选后 `Ctrl+C`。
4. 想复制整段对话：`Ctrl+Shift+C`。

### 对话模式：3 个模式，旧写法照旧可用

现在只有 **3 个模式**，编号 1/2/3，缩写 c/ct/ag：

| 模式 | 用途 | 温度预设 |
| --- | --- | --- |
| `chat`（默认） | 通用对话：办公问答、解释、写作、翻译…… | 0.7 |
| `contract` | 条款审查：逐条「原文摘录 → 风险点 → 修改建议」，金额/责任类结论必须提示人工复核 | 0.3 |
| `agent` | 智能体：模型自己决定调用哪个工具、按什么顺序，直到给出结论（见「六、Agent：让模型自己调工具」） | 0.5 |

每个模式仍写明**六要素**（角色 / 输出格式 / 详略 / 思维 / 示例 / 语气），并共享同一段通用要求
（不知道就说不知道、能一句话答完就一句话、信息不全先给最可能的答案再问、不编造出处）。

**被合并掉的模式，能力没有丢，改由 `/task` 任务模板承担**。旧写法仍然可用：程序会切到 chat
并自动套上同名模板，回复里也会说明「已并入其它模式、已自动套用 /task xxx」，温度沿用旧模式的预设
（不想要模板时用 `/task off` 取消）：

| 旧写法 | 现在等于 | 沿用旧温度预设 |
| --- | --- | --- |
| `/mode general` | `chat`（只是改名） | — |
| `/mode summary` | chat + `/task summary` | 0.4 |
| `/mode translate` | chat + `/task translate` | 0.3 |
| `/mode code` | chat + `/task code` | 0.2 |
| `/mode creative` | chat + `/task creative` | 0.9 |
| `/mode guide` | chat + `/task guide` | 0.6 |
| `/mode contract` | 不变，仍是独立的 contract 模式 | 0.3 |

**旧编号不再自动迁移（会明确报错并告诉你该写什么）**：编号在两套编号体系里会指不同东西
（旧的 `/mode 2` 是 summary，新的 `/mode 2` 是 contract），所以 4/5/6/7 这类旧编号不会被
"猜着切"——程序会回一句「编号已经变过：现在 1=chat、2=contract、3=agent，旧编号 4 当时指别的模式，
请改用 /task code」，避免出现"既不是旧语义也不是新语义"的状态。**建议直接写模式名**
（`/mode summary`）或"先切模式再套模板"（`/mode chat` + `/task code`）。

任务模板从 6 个增加到 **8 个**（新增 `creative` 创意写作、`guide` 需求澄清），`/task list` 看全部。

### 状态区的运行指标

状态区（输入框上方那一行）在生成期间会显示本次运行的实测指标，全部由后端上报，前端不做估算：

| 显示 | 含义 |
| --- | --- |
| `⏳ 等待首 token` | 已经开始生成，但模型还在处理输入（prefill）。纯 CPU 上这一步可能要十几秒 |
| `⚡ 首 token 0.85s` | 从发出请求到第一个 token 到达的时间 |
| `🚀 12.3 token/s` | 生成速度（思考内容也算在内，"变慢了"会如实反映） |
| `📤 128 tokens` | 本次生成的 token 数（带 `≈` 表示分词器不可用、按字符估算） |
| `⏱️ 3.40s` | 总耗时 |
| `⏹ 已中止` | 这一轮是你主动停止的，指标保留到下次提问才重置 |

没有模型时整块指标不显示（不显示 0 或占位符）。

### 一次上传多个文件

- **文件对话框**：`Ctrl` / `Shift` 多选或框选；**拖拽**：一次拖入多个文件。两种方式行为一致。
- 每份文件**单独显示状态**：`⏳ [3/8] 合同.docx …` → `✅ [3/8] 合同.docx（12345 字符）` 或
  `❌ [3/8] … 解析失败`；**单个失败不影响其他**，结束时统一提示"已加载 N 个文件"。
- 一次最多 10 个文件、总量上限 60MB，超过会先询问是否继续（继续则只处理前 10 个）。
- 提问时**全部文件都会注入**（每份带 `【文件内容 N/M：文件名】` 标签）。
  总量超过 `config.json` 的 `files.total_chars`（默认 60000 字符）时，
  会**从最近上传的开始装**，没装下的会在回答前明确点名告诉你 —— 不会静默丢掉。
- 同名文件再次上传是**替换**而不是累积；超大文件（默认超过 20000 字符）的正文会落盘到
  `file_cache\`，上下文里只保留指针与摘要。
- 会话文件只保存文件名、体积与摘要，**不保存正文**：重开会话后，有摘要的文件仍可基于摘要回答，
  没有摘要的会提示你重新上传。

### 让本地小模型答得更稳

- **任务模板**：`/task list` 列出 8 个模板——摘要归纳（`summary`）、合同条款审查（`contract`）、
  结构化抽取（`extract`）、翻译（`translate`）、代码解释与排错（`code`）、推理判断（`reason`）、
  创意写作（`creative`）、需求澄清（`guide`）。
  用 `/task contract` 套用（可以只写前缀，如 `/task con`），`/task off` 取消。
  模板与**当前模式叠加**生效：模式负责场景与语气，模板负责本轮的输出格式，两者冲突时以模板为准
  （提示词里写明了这条优先级）。`/prompt <文本>` 优先级最高，会盖住模式与模板——
  想恢复模板先 `/prompt reset`；`/task off` 只取消模板，不会动你设的自定义提示词。
- **回答语言**：跟随界面语言。中文界面要求简体中文，英文界面要求英文；
  若你自己加了别的语言包，模型会跟随你提问所用的语言。提示词正文本身保持中文，不影响这点。
- **每个模式都有完整的提示词**：3 个模式各自写明角色、输出格式、**详略判断**、推理步骤、
  一个输入输出示例与语气，并共享同一段"通用要求"（不知道就说不知道、能一句话答完就一句话、
  信息不全先给最可能的答案再问、不编造出处）。
  详略那一项是告诉你"它可以自己判断该说多少"：简单问题不必套满格式，复杂问题仍会分点。
- **说不清想要什么就用需求澄清模板**：`/task guide` 会先列出 2~3 种"你可能想问的"方向，
  每种配一句它会怎么做，你回一个编号（或说"都不是"）即可，不用自己先想清楚怎么描述。
  旧写法 `/mode guide` 也可以：它现在会自动切到 chat 并套上这个模板。
- **生成预设**：`/preset list` 查看；`light`（轻量，回复短、最快）/ `balanced`（均衡，默认）/
  `quality`（高质量，回复最长）会一键切换温度、top_p、重复惩罚与回复长度上限。切换结果记入配置，
  重启后仍然生效；之后再手动用 `/temp` 改温度时以手动值为准。
- **压缩上下文**：`/compact` 立刻把较早的对话压成摘要腾出空间（配置项 `context_mode` 设为
  `slide` 时改为直接丢弃最早的历史），不必等占用到阈值才自动触发。
  自动触发的阈值与保留策略在 `config.json` 的 `compact` 段：`trigger_ratio`（默认 0.70，
  即占用到窗口 70% 时压缩）、`grace_turns`（默认 3，最近 3 轮**逐字保留**不动）。
  想指定压缩时特别保留什么，用 `/compact focus on 合同金额`（重点是**追加**到摘要要求里，
  不是替换）。每次压缩都会往 `compact_log.jsonl` 记一条事件（触发原因、前后占用、
  压缩条数、摘要全文），可读可审计；涉及敏感内容时把 `compact.log_content` 改为 `false`
  即可只记长度不记摘要正文。
- **提问太模糊时它会先"给方向"而不是要材料**：例如只发「这个怎么办」，且既没有文件上下文
  也没有历史时，程序会列出 2~3 种可能的意思（要处理某份材料 / 要一套做法 / 要排查某个报错……）
  并各给一句它会怎么做，你回一个编号就行——**不再反过来要求你先说清对象、输出形式和约束**。
  在需求澄清模板（`/task guide`）下这一步交给模型现列，方向会更贴合你那句话。
  已经聊了几轮或上传了文件时不会再触发（那时"这个"通常指的是上文内容）。
  不想要这一步可在 `app\backend\config.json` 里把 `clarify_vague` 改为 `false`。

## 三、场景一：审查长合同

**目标**：让本地模型基于一份几十页的合同回答问题，且不因超出窗口而丢信息。

1. `Ctrl+O` 或直接**把文件拖进窗口**（支持 docx/xlsx/pptx/pdf/txt 等）；
2. 若文件很长，EchoDesk 会自动先做**分段摘要**（对话框里能看到「正在摘要第 N/M 段」），
   完成后提示原文被压缩成了多少 token，并给出**原文指针**；
3. 提问时**提到文件**（例如「这份合同的付款条款是怎么约定的？」「有哪些违约风险？」）；
4. 若摘要粒度不够、想看细节：
   - 用 `/summarize` 重新生成一次摘要；
   - 或把合同按章节拆成几份分别上传；
   - 或临时调大 `app\backend\config.json` 的 `context_length`（越大越慢、内存占用越高，
     `/status` 会显示 KV Cache 估算）；
   - 或直接问细节问题：EchoDesk 会**检索最相关的片段**（带文件名与字符区间）一起注入，
     比只看摘要更容易落到具体条款（见「九、检索与引用溯源」）；
5. 想把结论存档：`/save 合同审查意见`。

**判读状态**：`/status` 里的「上下文: 约 X/Y tokens」显示当前占用与自动摘要线（窗口的 80%）。

**摘要会缓存**：同一份文件第二次上传会直接复用上次的分段摘要，不重新计算；文件内容改动后缓存自动失效。
缓存写在 `app\backend\summary_cache.json`（可读 JSON，直接删除即可清空），
不想用缓存可在 `app\backend\config.json` 里把 `summary_cache` 改为 `false`。

## 四、场景二：批量审核网页上的合同（自动化）

**目标**：某个系统的任务列表里有若干任务，每个任务挂着合同附件，需要逐个下载并生成审核意见。

### 4.1 一次性配置（设置窗口 → 自动化）

| 字段 | 填什么 | 示例 |
| --- | --- | --- |
| 任务列表网址 | 列出全部任务的页面 | `https://oa.example.com/tasks` |
| 任务列表元素位置 | 指向「任务链接」的 CSS 或 XPath | `a.task-link` 或 `//a[@class='task']` |
| 任务行容器（可选） | 分页/行级定位用 | `table.task-table tr` |
| 下一页按钮（可选） | 翻页 | `a.next-page` |
| 任务详情页文件元素位置 | 指向附件链接 | `a.attachment` |
| 需要预览的文件后缀 | 逗号分隔 | `pdf, docx, xlsx` |
| 任务指令 | 交给模型的提示 | 「摘取合同的主要信息并生成财务审核意见」 |

填完点**「测试选择器」**：程序会打开浏览器访问该网址，把匹配到的元素文本与链接
预览在日志里——**先确认能匹配到正确的元素，再开启运行**。

### 4.2 安全协议
勾选「我已阅读并理解上述安全协议」后，自动化开关才可用（后端会强制校验）。
协议版本与你的同意时间会记入 `app\backend\automation_log.jsonl`。

### 4.3 运行
- 点「▶ 立即运行一次」；
- 浏览器会**有头打开**（你能看到全过程），逐个任务：进入详情 → 下载符合后缀的文件 →
  本地解析 → 交给本地模型生成摘要与审核意见 → **删除该任务的临时文件** → 下一个；
- 过程中日志实时刷新（也能在主窗口对话框看到）；
- 遇到**验证码或二次验证**会暂停并提示你手动完成（默认最多等 180 秒）；
- 想中止：设置窗口点「⏹ 停止自动化」，或回主窗口按 `Esc`；
- 单个任务失败会**截图存证并跳过**，不会中断整批（截图与失败原因都留在该任务的结果目录里）。

### 4.4 定时
勾选「启用定时」并填写每天的执行时刻（如 `09:00, 18:30`）。
定时任务由后端线程在程序运行期间触发；若希望开机自动执行，
请把「Start-EchoDesk-v0.2.2.lnk」复制到系统「启动」文件夹（`Win+R` → `shell:startup`）。

### 4.5 登录态
第一次需要你在浏览器里手动登录一次，程序会把登录态存到
`app\backend\browser_state.json`，之后自动复用。删除该文件即可退出所有登录。

## 五、场景三：安装技能扩展能力

1. `Ctrl+M` 打开设置窗口的**技能市场**；
2. 浏览或输入关键词搜索（输入后 300ms 自动搜索）；可切换「Star 最多 / 最近更新 / 最佳匹配」；
3. 卡片信息：
   - `✔ 已验证` = 仓库根目录有合法的 `skill.json`（含 `echodesk.bundle`）；
   - `⚠ 未验证` = 结构不合规，**安装按钮置灰**；
   - `● 已安装` = 本机已装，按钮变为「卸载」；
4. 点「详情」查看 README 摘要、版本、依赖、入口文件、是否含 prepare 脚本；
5. 点「安装」会弹出确认框，列出技能名、版本、来源链接与安全提示——
   确认后下载源码、校验清单、登记注册表。
   **EchoDesk 不会自动执行第三方脚本**；若技能声明了额外依赖，会在提示里列出，由你决定是否手动安装；
6. 「已安装」按钮可查看本机技能清单。

技能来源：**只从 GitHub topic `echodesk-plugin` 发现**。
搜不到结果通常是该 topic 下暂时没有仓库，而不是程序故障（详见 FAQ）。

### 本地插件与开发者模式

设置窗口「开发者」页的**开发者模式开关双向可用**：关掉就是关掉，重启后仍保持关闭。

- 关闭开发者模式会**卸载开发插件**并从指令表移除，同时清空开发日志 `app\backend\skills_dev.log`；
- 首次加载**第三方本地插件**（放在 `app\backend\skills_dev\`）会弹出**一次**汇总确认框：
  逐项列出插件的来源、路径与声明的能力、权限，可以**逐个勾选 / 全部启用 / 全部禁用**；
  你的选择会被记住，拒绝过的插件下次不再询问；
- **随包示例插件**（`examples\skills\` 下的 Hello World 与 OFD 读取）默认启用，不弹确认框。

## 六、Agent：让模型自己调工具

**Agent 模式**下不再由你指定步骤：模型自己决定调用哪个工具、按什么顺序，直到给出结论。
与普通对话的差别只有这一点，其余（上下文、历史、停止）完全共用。

进入方式：`/mode agent`（也可 `/mode 3`、`/mode ag`），或在对话框里 `/agent on`；
`/agent off` 切回普通对话。Agent 模式的温度预设是 **0.5**。

### 6.1 工具清单：两档权限

| 档 | 工具 | 能做什么 | 默认 |
| --- | --- | --- | --- |
| ✅ 安全 | `calc` | 四则运算、`**`、`%`、括号与 `sqrt`/`round`/`abs`/`min`/`max`/`log` 等函数；用 AST 白名单求值，**不是 `eval`** | 可用 |
| ✅ 安全 | `date` | 当前日期、日期加减、两天相差天数、某天是星期几 | 可用 |
| ✅ 安全 | `convert` | 长度 / 质量 / 面积 / 体积 / 数据 / 时间 / 速度 / 压力 / 温度换算 | 可用 |
| ✅ 安全 | `doc_search` | 在你**已上传的文件**里按关键词找相关段落（返回文件名与片段） | 可用 |
| ✅ 安全 | `doc_summary` | 取已上传文件的摘要 | 可用 |
| 🔒 敏感 | `web_search` | 联网搜索（会把关键词发到互联网） | **关闭** |
| 🔒 敏感 | `file_read` | 读取本机**文本类**文件（单个文件上限 512 KB） | **关闭** |

- **敏感工具必须显式授权**：`/agent allow web_search` 打开、`/agent deny web_search` 收回，
  写进 `config.json` 的 `agent.allow_sensitive`，**长期生效**（不必每次对话确认）；
  设置窗口的「智能体」页同样可以勾选。
- **本版不提供任何写文件或执行命令的工具**（权限最小化）。
- 没被授权的工具**不是静默失败**：对话里会显示 🔒 与"未启用、怎么开"，模型据此继续用已有信息作答。
- `/agent list` 看工具清单与授权状态；`/agent steps 5` 把步数上限改成 1–8（默认 4）。

### 6.2 每一步都看得见，随时可停

对话里会按顺序显示每一步：

```
📍 第 1/4 步
🔧 调用 calc 参数 {"expr": "(128.6*10000)*0.003"}
↩ calc 返回：3858.0 （3 ms）
```

工具结果会回灌进上下文（单条结果有长度上限），所以模型能"看着结果再决定下一步"。
按 `Esc`（或点 ⏹）可随时停止——与普通对话**走同一个停止路径**。
达到步数上限时会自动收敛：不再调工具，改成"用已有信息给结论"，因此你总能拿到一段结论。

### 6.3 与自动化有什么不同

| | 自动化 | Agent |
| --- | --- | --- |
| 流程 | 你在设置里配好选择器，程序跑**同样的预定义流程** | 模型**自主决定**用哪个工具、按什么顺序 |
| 形态 | 批量：列表页 → 逐个任务 → 下载 → 审核意见 | 单次任务：一次提问内解决 |
| 谁在驱动 | 固定脚本（Playwright 有头浏览器） | 模型（每次可能不同） |

## 七、接入外部工具：MCP

MCP（Model Context Protocol）让 Agent 用上**外部进程**提供的工具（数据库、API、文件系统……）。
EchoDesk 自带一个 **stdio 传输的 MCP 客户端**（零新依赖），你在配置里写一行命令即可接入。

### 7.1 配置一个 server

`app\backend\config.json` 的 `mcp` 段：

```json
"mcp": {
  "enabled": false,
  "timeout_seconds": 20.0,
  "auto_connect": false,
  "servers": [
    {"name": "echo", "command": "python", "args": ["examples/mcp/echo_server.py"], "enabled": true}
  ]
}
```

随包示例服务器在 `examples\mcp\echo_server.py`（纯标准库，提供 `echo_text` 与 `now` 两个工具），
可以直接配上它验证通路。接进来之后，工具会以 `mcp__echo__echo_text` 这样的名字出现在 `/agent list` 里。

### 7.2 指令

```
/mcp                        查看状态与工具
/mcp enable echo            启用某个 server（写进 config.json）
/mcp disable echo           停用（立即生效，无需重启）
/mcp connect                立刻连接并拉取工具清单
```

设置窗口「**智能体**」页的 MCP 小节里同样可以改（总开关、启动时连接、超时、每个 server 的
启用/停用、添加或删除 server、「连接并取工具」按钮），与这些指令完全等价。

### 7.3 安全边界（必读）

- MCP Server 是**你自己配的外部进程**，EchoDesk 无法控制它的行为；
- 所以它的工具**一律按敏感工具处理**，必须先 `/agent allow mcp__<server>__<tool>` 授权；
- 默认**不透传**父进程的环境变量（密钥不会顺手交给第三方进程）；要透传就在该 server 的
  `passthrough_env` 里点名；
- EchoDesk **不会自动发现、也不会自动连接**任何地址；`auto_connect` 默认 `false`，
  只有你执行 `/mcp connect`（或把它设为 `true`）才会真的拉起进程。

### 7.4 与"数据不出本机"的关系

这一条要说清楚：**MCP 是否联网、数据流向哪里，取决于你配置的那个 server 进程**。
EchoDesk 自身不主动外联，也不替你决定把数据发给谁——它只拉起你写的命令，把工具结果取回来。
因此"数据不出本机"这条承诺在**默认配置下依然成立**（默认不开 MCP、也没有任何 server）；
一旦你自己接了 server，数据边界就由那个进程决定，请只接入你信任的 server。

### 7.5 本版限制 / 与技能的区别

- 本版**只支持 stdio 传输**：不支持 HTTP/SSE，也不支持 resources / prompts / sampling。
- 与**技能**（skills）的区别：技能是"给 EchoDesk 加功能"（能注册指令、面板、钩子、文件解析器，
  从技能市场安装）；MCP 是"让 Agent 多几个外部工具"（只提供工具调用，由你手写命令接入）。

## 八、模型管理与推理参数

### 8.1 推理参数面板（设置窗口 → 模型）

「模型」页新增了推理参数面板：四条滑块，每行都有「恢复默认」：

| 参数 | 范围 | 说明 |
| --- | --- | --- |
| 温度 | 0–1.5 | 越高回答越发散，越低越保守 |
| top_p | 0.1–1.0 | 候选词范围，调低更集中 |
| 重复惩罚 | 1.0–1.5 | 调高少复读，过高变生硬 |
| 最大生成 token | 64–4096 | 单次回复的长度上限 |

另外还有三项：**生成预设**下拉（light / balanced / quality，改了就生效）、**上下文策略**
（分段摘要 / 滑动窗口丢弃），以及两个开关（模糊提问先给方向、分段摘要缓存）。
点「保存」会**一次性写入并回读真实生效值**（不是把你拖到的数字当成已生效）；
点「重新读取」重新拉取当前值。

> 温度上限从 1.0 放开到 1.5，是与界面滑块对齐的结果：拖到头保存后又变回 1.0，
> 只会让人以为界面在骗人。

### 8.2 自定义模型档位

模型档位现在可以在设置窗口里**新增 / 修改 / 删除**，不必再手改 `config.json`：
可填别名、模型文件名或路径、仓库、上下文长度、温度与备注；别名重复即视为修改。

两点保障：

- **删除档位不会删除磁盘上的模型文件**——只删掉"这一档"的登记；
- **正在使用的档位拒绝删除**，会提示你先切到别的档位。

## 九、检索与引用溯源

新增了长文档**本地检索**（关键词 BM25，纯标准库、零新依赖）：提问时不再只能吃一份摘要，
最相关的片段会一起进上下文。

### 9.1 检索与分段摘要的分工

| 场景 | 用哪个 | 为什么 |
| --- | --- | --- |
| 短文档（全文能进上下文） | **全文注入，不检索** | 材料够短时全文最准，检索只会丢信息 |
| 长文档（已落盘或有摘要）+ 具体问题 | **摘要给全局 + 检索给细节** | 摘要负责"这份材料讲什么"，检索负责"30 个工作日那条在哪" |
| 长文档 + 泛问 | 摘要为主，检索只补 top-k | 泛问题没有可检索的关键词，硬检索会引入噪声 |

也就是说：**摘要是压缩，检索是定位**，两者互补而不是替代。检索到的片段会排在文件块之前，
你能一眼看出这次回答是基于哪几段。

### 9.2 引用溯源

注入的每个片段都带**位置**，形如：

```
[1] 采购合同.docx（字符 210-480）
乙方应在验收合格后 30 个工作日内支付合同金额的 95%……
```

同时明确要求模型用 `[编号]` 标注依据（没有依据的内容不要写成引用）。
拿着文件名与字符区间，你可以回原文核对，而不是只能相信一句话。

### 9.3 多文档问答与增量索引

- **不必点名文件**：检索跨所有已上传文件进行；需要时也可以限定只看某几份。
- **增量索引**：新上传的文件只索引那一份，已有文件不动；同名文件按最新内容替换；
  删除文件后，它的内容就检索不到了。

### 9.4 配置项

`app\backend\config.json` 的 `retrieval` 段：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 检索总开关 |
| `mode` | `keyword` | 本版只有 keyword；hybrid / vector 是给未来留的取值 |
| `chunk_chars` | 600 | 分块长度（约 300 token） |
| `overlap_chars` | 100 | 块间重叠，避免答案横跨块边界时漏掉 |
| `top_k` | 4 | 一次注入几段 |
| `max_context_chars` | 2400 | 注入片段的总长上限 |
| `min_score` | 0.0 | BM25 得分下限（0 = 不设阈值） |

### 9.5 为什么用关键词检索而不是向量库

这是有意的取舍：

1. **体积**：向量库（faiss / hnswlib / chromadb）加上嵌入模型，会给发布物增加几十到几百 MB，
   与"安装后 350–400 MB"的约束直接冲突；
2. **换模型会让索引失效**：嵌入向量与所选模型绑定，用户换对话模型时整个索引作废；
   关键词索引与模型无关，换模型不用重建；
3. **可解释、可核对**：关键词命中能直接说清"因为出现了这几个词"，向量相似度只能给一个数字——
   要做到"引用可溯源、用户能回原文核对"，关键词检索的溯源更可信。

## 十、联网与隐私速查

| 功能 | 是否联网 | 发送什么 |
| --- | --- | --- |
| 普通问答、文件解析、长文档摘要、本地检索 | ❌ 完全本机 | — |
| Agent 安全工具（计算 / 日期 / 单位换算 / 在已上传文件里检索与取摘要） | ❌ 完全本机 | — |
| Agent 敏感工具 `web_search`（需 `/agent allow web_search`） | ✅ 授权后才可能调用 | 当次提问关键词 → DuckDuckGo |
| Agent 敏感工具 `file_read`（需 `/agent allow file_read`） | ❌ 不联网，但会读取你指定路径的文本文件（≤512 KB） | 只读你指定的那个文件 |
| MCP（你自己配置的 server） | ❓ 取决于那个进程 | 由你配置的 server 决定；EchoDesk 只负责拉起它，不主动外联 |
| 模型下载 | ✅ 仅在你同意后 | 只下载，不上传任何内容 |
| 联网搜索（`/search on`） | ✅ 你手动开启后 | 当次提问关键词 → DuckDuckGo |
| 技能市场 | ✅ 打开市场时 | 搜索关键词 → GitHub API |
| 自动化 | ✅ 访问你填写的网址 | 仅在你配置的目标站点内操作 |

除以上之外，**没有任何遥测、埋点或崩溃上报**。详见 `docs/PRIVACY.md`。

**合规文档**：输入 `/about` 会显示版本号、出品方，以及这些文件的**本机实际路径**——
外层根目录的 `LICENSE`、`NOTICE`，与 `docs\PRIVACY.md`、`docs\EULA.md`、
`docs\THIRD_PARTY_LICENSES.md`、`docs\SBOM.json`。完整合规文档还包括 `docs\SECURITY.md`、
`docs\zh-Hans\COMPLIANCE.md` 与 `docs\en\COMPLIANCE.md`。

## 十一、键盘与效率

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+Enter` | 发送 |
| `Enter` / `Shift+Enter` | 换行 |
| `Esc` | 停止生成 / 关闭指令列表 |
| `Ctrl+L` | 清空对话 |
| `Ctrl+O` | 上传文件 |
| `Ctrl+Shift+C` | 复制全部对话 |
| `Ctrl+滚轮` / `Ctrl+加/减/0` | 调字号 / 重置 |
| `Ctrl+T` | 切换浅色 / 深色（三态在设置窗口「常规」页） |
| `Ctrl+,` | 打开设置 |
| `Ctrl+M` | 打开技能市场 |

**主题（三态）**：设置窗口「常规」页可选**跟随系统 / 浅色 / 深色**。选「跟随系统」时跟随 Windows 的
应用模式，你在系统里切换浅色/深色时界面会立刻跟着变。快捷键 `Ctrl+T` 在浅色与深色之间切换，
也可以直接用 `/darkmode on|off|auto` 指定。

**emoji 显示（三态）**：设置窗口「常规」页可选**自动 / 始终显示 / 不使用**。选「自动」时，
本机缺少 emoji 字体的话界面会自动改用纯文本标记（`[OK]` / `[!]`），而不是显示方块。

**状态区**：输入框下方一行实时刷新——搜索开关、自动化、技能市场、上下文占用、KV Cache 估算，
以及**模型能力项**（参数量 · 量化 · 可用窗口 · 实测生成速度）：

- 点「🧠 模型…」打开「设置 → 模型」查看完整能力与推荐配置；
- 模型能力边界被触到时（窗口偏小、生成速度过低、KV Cache 超过本机内存的一半等）才会出现
  「⚠️ 能力提示 N」按钮，点开逐条列出原因与可采取的动作；
- 点「🗜 压缩上下文」等同于执行一次 `/compact`。

**指令面板**：输入 `/` 会弹出指令列表，`↑↓` 选择、`Tab` 补全、`Enter` 执行。
左下角「+」可把输入框里的 `/xxx` 转移到独立的指令输入行。

**常用语**：点「📋 打开常用语选择框」一键插入模板；
用 `/snippet add 名称 文本` 新增、`/snippet list` 查看、`/snippet remove 名称` 删除。
