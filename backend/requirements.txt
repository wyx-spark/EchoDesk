# ⚠️ macOS 必须单独处理（v0.2.1 跨平台-2 实测，证据见 records/v0.2.2-跨平台-2记录.md）：
#   上游 cpu 索引发布的 **macOS arm64 轮子是坏的** —— wheel 字节数与上游 digest 完全
#   一致（也就是说"下完了、也没被篡改"），但包内 `lib/*.dylib` 大面积 CRC/魔数错误，
#   pip 安装必然失败。实测 0.3.21 / 0.3.30 / 0.3.35 / 0.3.36 的 cpu 索引 macOS arm64
#   轮子全部损坏；metal 索引（macOS 专用，对应 `vX.Y.Z-metal` 这些 Release tag）里
#   0.3.31 及以后同样损坏，**0.3.30 是最后一个完好的**（103 个成员全部可解压）。
#   因此 macOS 上用**直接 URL 钉死**这一个轮子：
#     * 直接 URL 而不是"索引 + 版本号"：两个索引里存在**同名但内容不同**的文件，
#       按索引挑是不确定的；钉 URL 才是确定的。
#     * 用 metal 而不是 cpu 构建对 macOS 本来也更正确 —— 它启用 Metal（Apple GPU）后端。
#   Intel Mac（x86_64）不在本轮三平台目标内（目标为 osx-arm64），换机器时把 URL 里的
#   `macosx_11_0_arm64` 换成 `macosx_10_9_x86_64` 并重新校验完整性即可。
# Linux / Windows 仍走 cpu 索引的常规解析（这两个平台的轮子实测完好）。
# Linux / Windows 必须装**官方 prebuilt wheel**，不能落到 sdist 源码编译：
#   cpu 索引 https://abetlen.github.io/llama-cpp-python/whl/cpu 上，
#   cp313-win_amd64 的轮子最高只到 **0.3.19**（0.3.20 及以后没有 cp313 的 Windows 轮子），
#   而不钉版本时 pip 会解析到最新版的 sdist 并触发本地 CMake/MSVC 编译。
#   装法：pip install -r requirements.txt --only-binary=llama-cpp-python
#   若将来换 Python 3.11/3.12（cp311/cp312 轮子更新更全），可放宽本 pin。

# 【v0.2.2 收尾实测修正】这个 pin **只能给 Windows**：
