任务书-2 第一二批：抽取式预筛（任务四）+ 流式心跳与运行指标（任务五/七）+ 搜索链路（任务二）

任务四（长文档摘要性能优化）——新增抽取式预筛：
- backend/extractive.py：TextRank 选句 + 稀有度加权 + 事实密度自适应比例。
  纯标准库、毫秒级（3000 字符的段约 8 ms），不引入 jieba/numpy。
- 要点全是「只出现一次」的事实（金额/日期/期限），而 TextRank 只认「彼此最像的
  套话句」，故中心度与稀有度各占一半（α=0.5，由两个样本的保留率扫描定出）。
- 两遍选句：先按得分装预算，再按「每字符得分」回填，避免长句吃光预算挤掉短要点。
- 结构性标题（文档开头的「采购合同」）无条件保留；段短于 600 字符不预筛；
  超过 12000 字符直接跳过（实测 8000 句要 22.9 秒，预筛不该比模型还慢）。
- summarizer 接线：model_input 先预筛再送模型，原文区间仍指向原文，
  兜底文本用原文，预筛抛异常安全退回原文；SummaryResult 与进度事件带预筛统计。
- 实测 47KB：逐段抽取 50421 → 17880 字符（压缩 2.8 倍），总耗时 136 ms。
- tools/test_extractive.py 83 项；backend/deploy config.json 加三个配置项。

任务五（流式卡顿与爆发）——后端心跳：
- llm_engine._iter_with_heartbeat：读者线程 + 有界队列，prefill 阶段每 1.5 秒
  一次心跳，消费者不再被阻塞的 next() 卡住（此前无论怎么 flush 都没数据可刷）。
- 停止信号传进读者线程（否则停止后模型继续算、「停止」退化成「停止显示」）；
  并按「停止被发现时手上那一块」的序号精确截断，既交付用户已看到的内容，
  也不多交付用户没来得及看到的内容（既有中断回归用例逼出来的）。
- 前端：思考区重渲染与「滚动到底」纳入 50ms 节流（此前每个 delta 都重建
  FlowDocument + 全页测量）；prefill 阶段状态文案区分「正在处理输入/正在生成」。

任务七（状态区实时指标）——全新：
- llm_engine.StreamStats + Backend 在 done 与心跳里上报 stats：首 token 延迟、
  输出 token 数（模型真分词器精确数，估算时标注）、token/s、总耗时、是否中止。
- 前端状态区新增运行指标块：流式实时更新、首 token 前显示「等待首 token」、
  完成后保留、下次请求重置、失败显示失败、中止标注「已中止」、无模型整块隐藏。

任务二（联网搜索未被有效利用）——逐环节排查并修掉：
- search_engine 重写：结构化 SearchResult/SearchOutcome，失败不再返回字符串
  （旧实现把「搜索失败: …」当资料注入给模型）。
- 注入改成编号列表 + 明确引用指令 + 「不足就说不知道」的出口；
  条数默认 3→5、单条 400 字符、总长 3000 字符。
- 开搜索但没拿到可用结果时明确告知用户（区分失败与空结果），不再静默继续。
- Backend.search_diagnostics() 暴露四个环节（触发/返回/注入/利用）。
- tools/test_search.py 59 项；新增 sys.search_failed / sys.search_empty 双语键。
