## 一、盘点方法

双语覆盖不能靠"翻目录看着像"，因此按**可枚举的清单**核对，而不是凭印象：

```powershell
# 仓库里所有受版本管理的 Markdown（含未跟踪的新文件）
git ls-files '*.md'
git ls-files --others --exclude-standard '*.md'
```

再对每份文件判断它属于哪种双语形态，逐条落实。判据来自仓库既有约定
（`tools/check_lang.py` 的 `check_bilingual_pairs()` 与 `docs/en|zh-Hans/` 目录结构）：

| 形态 | 适用对象 | 判据 |
| --- | --- | --- |
| **成对文件** `X.md` + `X.zh-Hans.md` | `docs/` 根目录下的合规/共用文档，以及仓库根目录的项目级文档 | 英文默认版为准；中文译本含「以英文版为准」声明，英文版给出中文版路径 |
| **按语言分目录** `docs/<locale>/X.md` | 面向用户/开发者的指南 | `docs/en/` 与 `docs/zh-Hans/` 的**文件清单必须一一对应**（`check_lang.py` 强制） |
| **单文件双语** | 短小的指针文件、被工具按固定路径读取的文件、随包分发且不宜增文件的短说明 | 同一文件内先一种语言、`---` 分隔、再另一种语言（`docs/SECURITY.md`、`USAGE.txt`、`.github/PULL_REQUEST_TEMPLATE.md` 都是这个形态，属既有实践） |

## 三、本轮的具体改动

### 3.1 CHANGELOG 改为"英文正本 + 中文译本"

- `git mv CHANGELOG.md CHANGELOG.zh-Hans.md`，并在开头加「以英文版为准」声明；
- 新写英文 `CHANGELOG.md`（953 行），开头声明指向中文译本；
- 两份文件的 `#`/`##`/`###` 标题**数量与级别序列完全一致**（各 19 个），章节一一对应；
- 同轮次的自动化优化条目**中英两份都写了**（各自位于 `## v0.2.1` 的首个小节）。

为什么选"英文当正本"而不是反过来：仓库既有约定是**英文默认版 + `.zh-Hans.md` 中文译本**
（`README` / `SECURITY` / `NOTICE` / `CODE_OF_CONDUCT` / `LICENSE` / `PRIVACY` / `EULA` /
`ENCRYPTED_DOCUMENTS` / `THIRD_PARTY_LICENSES` 全部如此），`docs/en|zh-Hans/README.md` 里也把
CHANGELOG 列在"shared documents：每份都是英文默认版 + 中文参考译本"之下。
另外 `tools/build_release.ps1` 的输出文案**本来就写着"各含中英两份"**，这次是把实现补齐到与声明一致。

### 3.2 CONTRIBUTING 补中文译本

- 新增 `CONTRIBUTING.zh-Hans.md`（12 个 `##` 章节与英文版一一对应）；
- `CONTRIBUTING.md` 顶部加指向中文译本的声明行；
- 中文版里的**页内锚点改为按中文标题生成**（例如 `#ways-to-contribute` → `#参与方式`），
  否则目录点不动——这一点是刻意与"链接目标逐字保留"的取舍：**可用性优先**。

### 3.3 DEVELOPER 文档拆成双语 + 原路径改指针

- `git mv docs/DEVELOPER.md docs/zh-Hans/DEVELOPER.md`，加 `English version:` 行；
- 新写英文 `docs/en/DEVELOPER.md`（6 个 `##`、10 个 `###`，编号与中文版 1:1；
  文档内的架构图重建为对齐的方框，所有框与箭头保留）；
- `docs/DEVELOPER.md` 改为**双语短指针**，说明正文在 `docs/en/` 与 `docs/zh-Hans/` 下，
  并以英文版为准。这与既有的 `docs/SECURITY.md`（指向根目录安全策略正文）完全同构，
  `docs/en|zh-Hans/README.md` 里原本就有一句"`docs/SECURITY.md` 只是短指针"，这次把
  `DEVELOPER.md` 并入同一句话。
- 保持原路径有效的原因：根 `README`、用户手册、自动化指南、`CONTRIBUTING.md` 都链到
  `docs/DEVELOPER.md`，改成指针后**这些链接无需改动即继续有效**；
- `docs/en/SKILL_GUIDE.md` / `docs/zh-Hans/SKILL_GUIDE.md` 里的"`docs/DEVELOPER.md` 的扩展点一节"
  改为指向各自语言的正文路径，避免读者多点一次。

### 3.4 发布脚本与检查脚本同步

- `tools/build_release.ps1`：外层合规文档复制清单加入 `CHANGELOG.zh-Hans.md`、
  `CONTRIBUTING.md`、`CONTRIBUTING.zh-Hans.md`；必备清单（`$mustHave`）加入
  `CHANGELOG.zh-Hans.md`、`CONTRIBUTING(.zh-Hans).md`、`docs\en\DEVELOPER.md`、
  `docs\zh-Hans\DEVELOPER.md`；`USAGE.txt` 的文件清单与注释同步。
- `tools/verify_release.ps1`、`tools/make_installer.ps1`、`tools/check_installer_deliverables.ps1`：
  同样的必备文件清单补齐（否则安装程序交付物检查会漏掉新文档）。
- `docs/en/README.md`、`docs/zh-Hans/README.md`、根 `README.md`：文档索引表补上
  CHANGELOG/CONTRIBUTING 的双语路径与 DEVELOPER 的指针说明。

### 3.5 顺带修掉的英文文档缺陷

- `docs/en/USER_GUIDE.md` 快捷键表里残留中文：`` `Ctrl+滚轮` / `Ctrl+加/减/0` ``
  → `` `Ctrl+mouse wheel` / `Ctrl+plus/minus/0` ``（英文正本里不该出现中文按键名）；
- 英文 CHANGELOG 里同类残留一并修正（`🏪 市场`/`📁 本地`/`🔧 开发` → `🏪 Marketplace`/`📁 Installed`/`🔧 Developer`，
  `🗜 压缩上下文` → `🗜 Compact context`，`<模块>` → `<module>`，`<指纹>` → `<thumbprint>`）。
  保留原文的**历史文件名/目录名**（如 `批量处理结果\` → `results\` 这类"改名前后对照"必须原样保留）
  与**程序真的会输出的中文标记**（`【早期对话摘要】`、`[优先级]` 等）。

### 3.6 发布说明模板里的两处内容修正

补英文时逐条对照发现的既有问题，中英两半**同步修正**（不只改英文）：

1. **交叉引用指错步号**：`结果目录改名` 明明是「升级指引」安装程序路径下的**第 4 步**，
   原文却写「见下方升级指引第 3 步」（英文半同错）。已改为第 4 步 / step 4。
   ——这是"翻译时被迫逐字核对"带来的附带收益：译文必须先看懂原文，才可能发现原文自相矛盾。
2. **升级指引没提新的登录态目录**：v0.2.1 起登录态存在 `app\backend\browser_profile\`，
   而升级指引只让用户复制 `app\backend\browser_state.json`。已在两半的复制清单与「已知限制」里
   补上 `browser_profile\`（并说明首次运行仍会自动导入旧 Cookie，通常不必重新登录）。

同时验证了发布说明模板的占位符完整：`{{VERSION}}`×4、`{{TAG}}`×2、`{{DATE}}`×2、
`{{PACKAGE_LIST}}`×2、`{{SHA256_LIST}}`×2、`{{CHANGELOG_EXCERPT}}`×2（**中英各半各一份**，
共 28 处），与 `.github/workflows/release.yml` 里做的 6 次纯文本替换一一对应，
替换后不残留任何 `{{…}}`（子代理按 workflow 的替换块实跑验证过）。

## 四、仍然单语的，以及为什么

| 文件 | 为什么不补 |
| --- | --- |
| `docs/SBOM.json` | SPDX 物料清单，**是数据不是文档**：字段值是包名、版本、许可证标识符，没有可翻译的自然语言正文（说明性文字在 `docs/THIRD_PARTY_LICENSES.md`，那份已双语） |
| `backend/lang/*.json`、`frontend/Resources/Lang/*.json` | 语言包**本身就是双语机制**：同一组键各有 `zh-Hans` 与 `en` 两个文件，由 `tools/check_lang.py` 强制键集合与占位符一致 |
| `LICENSE`、`NOTICE` | 法律文本，**必须**保留英文原文；中文只作参考译本（已有 `.zh-Hans.md`），不能改写正本 |
| `.github/*.yml`、`.gitignore`、`.gitattributes`、`*.csproj`、`config.example.json` | 配置与自动化脚本，不是给人读的文档 |
| `records/*.md` | 内部研发记录（**不随发布物分发**，`build_release.ps1` 明确排除），按任务书要求只用中文 |
| `prompts/*.md` | 上游任务书原文，属输入资料而非项目产出 |

### 5.1 一处与本轮无关的环境观察（如实记录）

`python tools/gen_sbom.py --check` 报 **22 处不一致**（例如 anyio：清单 4.15.1 / 本机 4.14.2；
发布闭包里有 `httpx` 而清单里是 `httpx2`）。这与本轮改动**无关**，证据：

- `git status` 显示 `requirements.txt`、`docs/SBOM.json`、`docs/THIRD_PARTY_LICENSES.md`、
  `backend/EchoBackend.spec` **均未被本轮改动**；
- 报错性质是"本机 Python 环境里安装的包版本与生成清单时的环境不同"（本机 anyio 4.14.2、
  httpx 0.28.1、charset-normalizer 3.4.9），属**环境漂移**；
- 处理办法（脚本自带提示）：在与发布物一致的环境里重跑 `python tools/gen_licenses.py`
  重新生成清单，或修正依赖后重跑。本轮不改依赖，因此不动这两份清单。
