## 二、任务一：开源化改造

### 2.1 仓库结构整理（1.1）

* `.gitignore` 逐项核对，新增 v0.2.1 的运行时产物：`backend/skills_dev/`、
  `skills_local.json`、`skills_dev.log`、`automation_templates.json`、`/lang/`、`*.echodesk-auto`。
* **踩到的坑（值得记下来）**：一开始把外置语言包写成 `lang/`，这会连带忽略
  `backend/lang/`（内置语言包）与 `frontend/Resources/Lang/`。必须写 `/lang/`
  才能只匹配仓库根目录下的那个。已用 `git check-ignore -v` 逐条验证。
* 模型、发布产物、会话、常用语、界面状态、自动化结果、市场缓存、技能注册表、
  崩溃日志均已在忽略清单内；`git status` 无意外文件。
* **Token 历史核查**：`config.json` 的 `marketplace.github_token` 与
  `model_hub.hf_token` 所有历史提交中均为空字符串。核查方式：
  `git log -p -- backend/config.json deploy/config.json | findstr /i "token"` 逐条确认，
  命中的都是字段名与注释，没有任何真实凭据；`git log --all --diff-filter=A` 中也不存在
  含 Token 的文件。因此**不需要 `git filter-repo` 清理历史**，也就没有"必须让用户重新生成
  Token"的问题。默认配置里两个字段都是空的，并在注释里写明"建议放在
  `config.user.json`（已被忽略）而不是基础配置里"。

### 2.2 开源文档（1.2）

### 2.3 合规与许可证（1.3）

**核心动作：移除 AGPL 的 PyMuPDF，改用 BSD 的 pypdf。**

| 项 | 说明 |
| --- | --- |
| 问题 | PyMuPDF 是 AGPL-3.0（或 Artifex 商业许可），与项目采用的 Apache-2.0 不兼容，对外分发会产生著佐权义务 |
| 方案 | `backend/file_parser.py` 的 `_read_pdf` 改用 `pypdf`（BSD-3-Clause，纯 Python，无原生扩展） |
| 顺带收益 | 该依赖的安装体积从 **52.9MB → 约 1.4MB**；同时消除随包分发的 AGPL 组件 |
| 代价 | pypdf 不处理无文本层的扫描件（本来就需要 OCR，不在支持范围）；复杂排版的阅读顺序还原弱于 MuPDF。对"把正文交给模型"这一用途足够 |
| 防回归 | `EchoBackend.spec` 的 `EXCLUDES` 显式加入 `pymupdf`、`fitz`，确保不会被任何间接 import 重新打包进来 |
| 测试 | `tools/test_file_parsers.py` 原来用 PyMuPDF **生成** PDF 样本；pypdf 只能读不能写，因此改为用裸 PDF 语法手工拼一个含 xref 表的单页 PDF——测试同时验证了 pypdf 的文本提取，且不再要求安装 AGPL 库 |

`docs/THIRD_PARTY_LICENSES.md` 由 `tools/gen_licenses.py` 重新生成（48 个包）：
现在**唯一的高风险许可证只剩 PyInstaller**（GPLv2 + 官方例外，明确允许打包分发专有程序，
且只用于构建、不以库形式随产物使用）。文档开头加了 v0.2.1 合规变更说明，
并注明"本脚本读本机环境，发布前请在干净 venv 里重新生成"。

### 2.4 持续集成（1.4）

## 三、任务二：技能运行期加载器与本地插件接口

### 3.1 加载机制（2.2）

`backend/skills_runtime.py`：

1. **发现**：扫描 `skills_dev/`（开发）、`skills_local.json`（显式清单）、`skills/`（正式安装）三处；
2. **解析**：读 `skill.json` 的 `echodesk.bundle` / `entry`，解析入口文件或包目录；
3. **加载**：把**该技能自己的目录**加入 `sys.path`（卸载时移除，不污染全局）→
   `importlib.util.spec_from_file_location` 动态导入 → 调用 `register(api)`；
4. **异常隔离**：导入/注册/执行的任何异常都被捕获，写入 `skills_dev.log`（含完整堆栈），
   单个技能失败不影响其它技能，也不影响主程序启动；
5. **接线**：注册的命令进入 `command_handler` 的指令表，行为与内置指令完全一致。

### 3.2 技能 API（2.3）

`SkillAPI` 提供任务书要求的六类能力：

| 能力 | 方法 | 说明 |
| --- | --- | --- |
| 命令注册 | `register_command(name, handler, ...)` | 处理函数收参数列表，返回文本 / `(文本, 动作)` / 含 `text` 的 dict |
| UI 面板 | `register_panel(id, title, fields=, actions=, on_action=, render=)` | 面板只声明数据，前端用**原生控件**渲染，技能不碰 UI 代码（也避免了 WebView2 这类重依赖） |
| 自动化钩子 | `register_automation_hook(stage, handler)` | `before_task` / `after_download` / `after_summary` / `after_task` |
| 文件解析扩展 | `register_file_parser(ext, handler)` | 未识别的扩展名先问已加载技能，再回落"不支持" |
| 配置读写 | `get_config()` / `set_config()` | 存于技能目录内的 `config.json`，与主配置隔离 |
| 多语言资源 | `lang(key, default, **kw)` / `lang_value()` | 技能自带 `lang/<locale>.json`，随界面语言切换 |

### 3.3 安全设计（2.4）

* **加载白名单**：`installed` 来源的技能必须在 `skills_registry.json` 中有记录；
  若市场验证缓存对该仓库有**明确的"未通过"记录**则拒绝加载。开发/本地来源走独立的放宽路径并单独标注来源。
* **异常隔离**：三层（导入、注册、执行）全部包了捕获与日志。
* **资源限制**：首版按任务书"可只做日志记录"执行——环境变量清洗 + 日志留痕，未做内存/CPU 配额。
* **卸载热重载**：从 `sys.modules` 移除模块（含子模块）、从 `sys.path` 移除目录、
  撤掉命令与解析器与钩子。
* **API 版本校验**：`echodesk.api_version` 主版本号一致即兼容，不一致拒绝加载并给出原因。

### 3.4 本地插件接口（任务二·补）

| 需求 | 实现 |
| --- | --- |
| 两个层级的目录 | `backend/skills_dev/`（开发，更宽松、不写注册表）与 `backend/skills/`（正式安装，共用注册表） |
| 清单文件 | `backend/skills_local.json`：任意路径（相对路径以**程序目录**为基准）、别名、启用/禁用、加载顺序、备注、信任状态 |
| 优先级与冲突 | `skills_dev/` > 清单指定路径 > `skills/`。同 ID 冲突时保留高优先级那份，并把被覆盖的路径记在记录里（界面显示「已覆盖：…」），日志里给出「当前加载的是开发版本，已覆盖已安装版本」 |
| 开发模式特性 | 放宽验证（缺 `echodesk.bundle` 只告警）、详细日志到 `skills_dev.log`（含堆栈）、热重载按钮、失败插件红色标记 + 错误详情、不写正式注册表 |
| 脚手架 | 设置窗口「➕ 新建本地插件」→ 生成 `skill.json` / 入口文件 / 双语语言包 / README 的最小骨架 |
| 安装与卸载 | 「📥 从文件夹安装」（可选装到 `skills_dev/`）、卸载（`skills/` 清注册表 + 删目录；`skills_dev/` 只删目录）、导出 zip |
| 与市场的关系 | 运行期同一套加载器、API 完全一致；界面标注 `🏪 市场`/`📁 本地`/`🔧 开发`；发布自检清单 + topic 指引；市场搜索命中本地已有开发版本时标注 |
| 安全 | 执行前**临时移除** `os.environ` 中名称含 KEY/SECRET/TOKEN/PASSWORD/CREDENTIAL 的变量，执行后恢复；首次加载未知来源本地插件弹确认框；界面展示技能声明的权限 |

### 3.5 示例技能（2.5）

`examples/skills/hello-world/`（命令 + 面板 + 自动化钩子 + 配置读写 + 双语）与
`examples/skills/ofd-reader/`（`.ofd` 文件解析扩展，用 `zipfile` + `xml.etree` 零依赖实现）。

`backend/skills_dev/`（开箱即用）与 `examples/skills/`；仓库里不提交 `backend/skills_dev/`。
设置窗口「开发者」页也提供「📦 安装示例插件」按钮随时装回。

**未能完成**：把示例技能真正发布到 GitHub 并打上 `echodesk-plugin` topic（需要仓库凭据，

## 四、任务三：多语言与语言包

### 4.1 机制

| 需求（任务书 3.4） | 实现 |
| --- | --- |
| 自动检测 | 后端 `GetUserDefaultLocaleName`/`locale`/`LANG`；前端 `CultureInfo.CurrentUICulture`；统一归一化（`zh-CN`→`zh-Hans`、`zh-TW`→`zh-Hant`、`pt-BR` 特例） |
| 手动切换 | 设置 → 常规 → 界面语言下拉（只列出实际存在语言包的语言 + 「自动」） |
| 即时刷新 | 前端 `Loc.Apply()` 按 XAML 里的 `svc:Loc.Key` / `Loc.HelpKey` / `Loc.TipKey` 附加属性回填文本；切换语言对已打开窗口重跑一遍即可。**无需重启** |
| 持久化 | `ui_state.json` 的 `language` 字段（前端权威）；后端另留 `config.json` 的 `language` 供无界面场景使用 |
| 回退链 | 当前语言 → `en` → `zh-Hans` → **键名本身**（刻意如此：缺键时界面上一眼能看出，而不是空白） |
| 后端同步 | 切换时发 `set_language`，后端系统消息、错误提示与指令帮助随之切换，并回传本地化后的指令表供前端重建指令面板 |
| 按需加载 | 只加载当前语言与回退链上的语言，不把全部语言读进内存 |
| 模块分片 | 支持 `<locale>.<模块>.json`，与主文件合并（任务书 3.5 要求"按模块拆分便于协作"） |

### 4.2 语言包文件

```
backend/lang/zh-Hans.json              351 条  后端正源
backend/lang/en.json                   351 条
backend/lang/zh-Hans.automation.json     ↳ 自动化字段标签/帮助/模板（模块分片）
backend/lang/en.automation.json
frontend/Resources/Lang/zh-Hans.json   371 条  前端正源
frontend/Resources/Lang/en.json        371 条
frontend/Resources/Lang/*.main.json      ↳ 主窗口追加文案
frontend/Resources/Lang/*.settings.json  ↳ 设置窗口追加文案
```

* 键名语义化、按模块分组（`settings.automation.task_url.label` 风格），
  以 `_` / `//` / `$` 开头的键视为给翻译者的注释，程序忽略。
* 单条文案可写成 `{"text": "...", "comment": "上下文说明"}`。
* 语言包**不嵌进程序集**：发布到程序根目录的 `lang\`，因此翻译者/社区可以直接往
  `lang\` 里丢一个新 `*.json` 贡献语言，无需重新编译（前端与后端都按同一优先级查找）。
* 语言展示名一律用该语言自己的写法（`简体中文` / `English` / `日本語` …）。

### 4.3 指令帮助的架构调整（顺带解决了一个隐患）

任务书要求"技能的命令与内置命令在指令面板中同等展示"。为此把指令元数据
（名称、用法、说明、分组、是否有副作用）从**前端硬编码表**改成
**后端语言包 + `{"action":"commands"}` 动作**：

* `/help` 与前端指令面板共用同一份数据源，装/卸技能后自动出现/消失；
* 命令说明随界面语言切换，不再需要在前端重复维护一份翻译。

同时修掉两处"靠中文字符串判断状态"的隐患（切英文后会失效）：
`/mode` 的结果不再靠匹配 `"✅ 已切换模式为: "` 前缀，搜索开关不再靠 `"搜索已开启"` 子串，
改为后端在响应里给 `mode` / `search` 机器可读字段。

### 4.4 翻译工作流（3.5）

* `tools/check_lang.py`：对比各语言与源语言的键集合（缺失/多余）、**占位符一致性**，
  并扫描代码里引用但语言包里没有的键；`--scaffold <locale>` 生成新语言模板；
  有缺失时退出码 1（CI 门禁）。
* `tools/extract_strings.py`：盘点尚未收编进语言包的界面文本（含注释/文档字符串过滤与
  上下文判定），`--json` 输出报告，`--scaffold` 复用 check_lang 的模板生成。
* `CONTRIBUTING.md` 有「翻译贡献流程」章节；`.github/ISSUE_TEMPLATE/translation.yml` 是对应模板。

### 4.5 覆盖率与未完成项

* **已完整多语言化**：全部指令帮助与指令元数据、后端系统消息与错误提示（启动、
  模型缺失、推理失败、忙碌/停止、更新检查）、文件解析错误（内部保持语言无关的失败标记，
  展示时经 `file_parser.localize_error` 本地化）、主窗口全部静态文案与状态区、
  设置窗口全部静态文案与标签、自动化字段标签/帮助/示例/预置模板、安全协议正文、
  退出确认与危险指令确认、首次启动引导、技能/开发者页文案、技能自带语言包。
* **仍为中文**：自动化、技能市场、模型中心的**逐条进度与深层诊断消息**

## 五、任务四：自动化配置向导与填写帮助

### 5.1 可视化选取（4.2）—— 关键技术决策

任务书指定用**内嵌 WebView2**。本版改用**Playwright 驱动本机 Edge**（自动化本来就用它），
理由记录如下（这是本次最需要说明的偏差）：

1. **与全局体积要求冲突**：WebView2 需要引入 SDK 并依赖系统 Evergreen 运行时，
   而任务书全局要求"每个任务同步检查可减小打包体积的机会"；
2. **任务书自己要求的"登录态与自动化共享（复用 `browser_state.json`）"WebView2 做不到**：
   它有独立的用户数据目录；Playwright 这套直接复用同一份 `browser_state.json`，
   登录态天然一致，且新登录态会写回该文件；
3. **复用同一渲染引擎更可靠**：选择器在 Edge 里生成、也在 Edge 里验证；
4. **可测试性**：选取器能写成端到端测试（本地 HTML 表格/列表/卡片三种布局下
   验证"生成的 CSS 选择器能唯一定位被点元素"），WebView2 只能靠 UI 自动化。

功能上完全满足任务书要求：打开内嵌浏览器 → 页面顶部蓝色提示条 →
悬停高亮 + 实时显示选择器预览与匹配数量 → 点击即生成选择器并回填字段 → Esc 取消。
支持四种选取目标（任务列表元素 / 任务行容器 / 下一页按钮 / 详情页附件），
最后一种会**先用任务列表选择器自动进入第一个任务**再开始拾取。
任务书要求的"WebView2 不可用时的降级"由「手动输入 + 测试」与字段旁「?」说明天然覆盖。

### 5.2 字段级帮助（4.3）

27 个自动化字段的标签、通俗说明、示例值全部放在语言包里
（`backend/lang/<locale>.automation.json`），通过 `automation_field_help` 动作提供给前端：

* 8 个核心字段（网址、任务列表元素、任务行容器、下一页按钮、详情页附件、文件后缀、
  任务指令、任务名称）旁有 **「?」按钮**：悬停显示说明，点击弹出说明 + 示例；
* 文本框获得焦点时，模板区下方**内联帮助面板**实时显示该字段的说明与示例；
* 其余运行参数字段的标签挂 ToolTip；
* 「📖 填写帮助」按钮汇总全部字段（含必填标记、分步标题、示例）在一个窗口里展示。

### 5.3 模板库与测试向导（4.4 / 4.5）

* 四个预置模板（合同财务审核 / 发票信息提取 / 报告要点汇总 / 表格数据核对）内容取自
  任务书表格，经语言包提供；一键填入「任务指令」与「需要预览的文件后缀」；
* 支持「存为自定义模板」（存 `automation_templates.json`，已加入 .gitignore）；
* 「测试向导」四步：① 测试任务列表元素（含任务行容器加分项）② 测试下一页按钮
  （会真的点一次并报告页面是否跳转）③ 测试详情页附件（自动进入第一个任务，并统计
  多少个附件的后缀在允许范围内）④ 试运行一个任务（`dry_run`：不建结果目录、不写
  `结果.txt`、不记处理记录）。每步给出成功/失败原因与**具体修正建议**。

### 5.4 配置导出/导入（4.7）

`.echodesk-auto` 文件：导出**排除**登录态文件、处理记录与临时下载目录；

文件语言与当前界面语言不同时给出提示但不阻断导入。

### 5.5 文档（4.6）

### 9.3 未能优化的体积项与原因

* **Playwright 的 Node 驱动（约 102MB）**：自动化功能完全依赖它启动本机 Edge，
  换成 pyppeteer/selenium 会引入别的驱动，且体积相当。保持不动。
* **llama.cpp 运行库（约 10MB）**：本地推理的核心，无法裁剪。
* **模型文件（507.8MB）**：按设计不在源码仓库与不含模型的包内；含模型包必然这么大。
* **PyInstaller 收集的 `_internal` 冗余**：已排除 torch/tensorflow/easyocr/cv2/scipy 等
  重型栈；剩余部分（pydantic/huggingface_hub/playwright 的数据文件）都有实际用途。
  进一步裁剪需要按 import 逐个验证，收益与风险不成比例。
* **UPX 压缩**：`upx=False` 沿用 v0.2.0 的决定——UPX 压缩会显著提高杀毒软件误报率，
  对一个面向企业内网的工具是净负面。

### 10.3 发版前发现并修掉的三个"只有对着真实产物才能发现"的问题

这三个都不是单元测试能发现的，也是本版坚持"重建发布物后重跑端到端"的价值所在：

1. **打包后端一启动就崩**：`backend/main.py` 缺少 `List` 的导入，
   而函数返回注解在没有 `from __future__ import annotations` 时于**定义时**求值，
   于是 `NameError: name 'List' is not defined` —— `ast.parse` 语法检查完全看不出来。
   **已加防回归测试**：`tools/selftest.py` 现在新增一项"真实导入全部 18 个后端模块"
   （`test_imports`），语法检查骗不过它。
2. **界面全是语言键名**：前端界面语言包与后端语言包都叫 `<locale>.json` 且都发布到
   `lang\`，后一个覆盖前一个，于是界面显示 `main.status.ready` 而不是"已就绪"
   （UI 探针直接读出了这个字符串）。**已修**：界面语言包改放 `lang\ui\`，
   `Localization.cs` 的搜索路径同步调整，并在 `test_i18n.py` 里加了防回归断言。
3. **设置窗口一打开就写崩溃日志**：遍历控件树时对 `ColumnDefinition`
   （不是 `Visual`）调用 `VisualTreeHelper.GetChildrenCount` 抛
   `InvalidOperationException`。**已修**：遍历前先判断是否为 `Visual`/`Visual3D`。

另外修掉了 XAML 里一处多余逗号（`</Grid>,`）导致的 `XamlParseException`
（"无法将 String 添加到 UIElementCollection"）——设置窗口完全打不开。
