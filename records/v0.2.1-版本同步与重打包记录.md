# v0.2.1 版本同步与重打包记录（发布物 ↔ 合规清单对齐）

> 本文记录 v0.2.1 发布前的最后一步收尾：修掉"发布物里的库版本与合规清单声明不一致"的根因，
> 用**干净 venv** 重建后端并重打两份安装程序，实测逐项一致，并补上会拦住同类漂移的门禁。
> 结论性数字（体积、SHA256、标签）同时写进了 `records/v0.2.1-发布记录.md` §21（当前生效口径）。

## 一、问题与根因

上一轮收口合规清单时发现：随发布物分发的 `docs\SBOM.json` 对若干个包声明了
**从未随包分发**的版本号。发布物 `app\backend\_internal` 里保留了 11 个 `.dist-info`，
其版本与本机**全局**开发环境 11/11 一致，却与清单所依据的干净 venv 有 **6 处**不同：

| 包 | 旧发布物（`_internal`） | 清单 / SBOM 声明 |
| --- | --- | --- |
| click | 8.4.2 | 8.5.0 |
| cryptography | 50.0.0 | 50.0.1 |
| huggingface_hub | 1.27.0 | 2.0.0 |
| numpy | 2.5.2 | 2.5.3 |
| pydantic | 2.13.4 | 2.13.5 |
| tqdm | 4.70.0 | 4.70.1 |
| duckduckgo_search / llama_cpp_python / MarkupSafe / playwright / pywin32 | 一致 | 一致 |

> **更正**：上一轮的记录与汇报写的是"**5 处**"，漏了 `tqdm`。这是人工逐项比对时漏行造成的。
> `records/v0.2.1-清单环境收口记录.md` 第五节已加更正说明；本轮的版本门禁回放脚本
> 一次就报出 6 处，才把它暴露出来。**"人工比对表格"这件事本身就会漏 —— 这一条也是新门禁的存在理由。**

**根因**：`tools\build_release.ps1` 里写的是

```powershell
Invoke-Native "pyinstaller" @("--noconfirm", "--distpath", $stage, ...) "后端构建"
```

`pyinstaller` 是**裸名字**，解析到 PATH 上的
`C:\Users\backt\AppData\Local\Programs\Python\Python313\Scripts\pyinstaller.exe`（**全局开发环境**，
PyInstaller 6.22.1），而不是干净 venv 里的那一个（6.22.3）。PyInstaller 是按**运行它的
那个环境**分析依赖、收集 `.dist-info` 的，于是"发布物里是哪个版本的库"完全取决于 PATH
恰好指向谁。开发机全局环境里有 132 个发行包（78 个开发期残留），版本也普遍比干净 venv 旧。

**为什么既有检查全是绿的**：`check_bundled_packages.py` 当时只比"`_internal` 的顶层模块名
能否对应到已声明的发行包"（结果 0 可疑）；顶层模块名一个不差，**版本差异不在它的射程内**。

## 二、修根因：`tools/build_release.ps1`

| 改动 | 内容 |

| 新增参数 | `-CleanVenv`，默认 `artifacts\clean-venv`（支持绝对路径） |

| 文档 | 文件头 `.DESCRIPTION` 第 2 步与 `.PARAMETER CleanVenv` 都写明原因，避免以后被"顺手改回裸名字" |

**守卫实测**（不是只读代码）：用 `-CleanVenv artifacts\no-such-venv -SkipClean -SkipFrontend` 跑一次 →

## 六、新增门禁：让同类漂移当场失败

### 6.1 `tools/check_bundled_packages.py` 增加版本比对

原来只有"顶层模块名 → 发行包名"的比对，**版本不在射程内**。现在新增：

* `dist_info_versions()`：从 `_internal` 的 `*.dist-info` 目录名解析 `(名字, 版本)`，
  取**最后一个**连字符切分（`pywin32-ctypes-0.2.3` 这类自带连字符的包名也能正确切开）；
* `compare_versions()`：与干净 venv 清单逐项比对，分"一致 / 版本不一致 / 清单未声明"三类；
* 版本不一致或出现未声明组件 → **退出码 1**（原来是 0），并打印处理办法。

**单向比对**是刻意的：`.dist-info` 只有一部分发行包会留在 `_internal`
（纯 Python 包进 PYZ，元数据目录不一定被收集；本次 22 个可对应模块里只有 13 个带 `.dist-info`），
所以只要求"发布物里出现的每一个 `.dist-info` 都与清单对得上"，覆盖率会打印出来（本次 24%）。

### 6.2 `tools/check_installer_deliverables.ps1` 增加载荷断言

新增 `Assert-PayloadMatchesSbom()`，在既有的"真装真验真卸"里调用：
读**安装目录**的 `docs\SBOM.json`，与**安装目录**的 `_internal\*.dist-info` 逐项比对；
版本不一致、出现未声明组件、或比对到的项少于 5 个（防"`_internal` 不完整导致空过"）都算失败。
结果会拼进原有的 `Summary` 一起打印（见第五节）。

### 6.3 门禁有效性验证（回放旧发布物）

`artifacts\replay_old_artifact_gate.py` 把**修复前**发布物的 11 个 `.dist-info` 名字
（`artifacts/artifact-distinfo.txt`，实测清单）铺成假的 `_internal`，喂给新的
`compare_versions()`：

```
回放旧发布物的 11 个 .dist-info：
  一致 5 个 / 版本不一致 6 个 / 未声明 0 个
   ! click: 发布物 8.4.2 / 清单 8.5.0
   ! cryptography: 发布物 50.0.0 / 清单 50.0.1
   ! huggingface-hub: 发布物 1.27.0 / 清单 2.0.0
   ! numpy: 发布物 2.5.2 / 清单 2.5.3
   ! pydantic: 发布物 2.13.4 / 清单 2.13.5
   ! tqdm: 发布物 4.70.0 / 清单 4.70.1
```

**这条回放同时完成了两件事**：证明门禁能拦住那 6 处漂移；以及纠正"5 处"的少算。
（顺带踩到一个坑并已在脚本里注明：那份清单是 PowerShell `Set-Content -Encoding UTF8`
写的，PS 5.1 会加 BOM，不剥掉的话第一行会变成 `\ufeffclick` 而被误判成"清单未声明的组件"。）

## 八、可复现性（移动标签前的校验）

任务书要求"移动前确认新提交确实能复现出相同哈希的安装程序"。分两层实测：

**（1）同一载荷 → 安装程序字节一致 ✅**
用同一个 `tools\installer.iss` 与同一份 `publish\EchoDesk-v0.2.1` 重新编译一次
（输出到 `%TEMP%\echodesk_repro_test`）：

```
已交付产物 : 7CD36C51DB237CCB45F4660C28BAC09EAE1BEF4BC34A15A592B9DA7075079E22  (118819425 字节)
同源重建   : 7CD36C51DB237CCB45F4660C28BAC09EAE1BEF4BC34A15A592B9DA7075079E22  (118819425 字节)
字节相同? True        体积相同? True
```

**（2）从零重跑整条流水线 → 做不到字节一致（必须说清楚）**
PyInstaller 把构建时间写进了 PE 头：

| 可执行文件 | PE `TimeDateStamp` | 含义 |
| --- | --- | --- |
| `app\backend\EchoDeskBackend.exe` | `1790515629` = **2026-09-27 13:27:09 UTC** | 正好是本次构建时刻 → 每次重建都会不同 |
| `app\EchoDesk.exe`（前端 .NET） | `1769340928` = 2026-01-25 11:35:28 UTC | 固定值，不受构建时间影响 |

所以：**同一提交 + 同一工具链 ⇒ 相同的包内容与版本清单；同一载荷 ⇒ 安装程序字节一致；
但从零重建会在内嵌构建时间上不同。** 要让后端也字节可复现，需要在调用 PyInstaller 前
设置 `SOURCE_DATE_EPOCH`（PyInstaller 支持该约定，会同时用于 PE 时间戳与归档内时间）。
**本轮没有做**：它会使本轮刚验证过的产物再次失效，属于"另一次完整重建 + 重验"的独立改动，
已列在第九节，等确认后再做。

标签因此按"**检出该提交即可重现出这一组产物**（内容与版本口径一致）"的含义移动。

## 九、观察与未做

* **未做 `SOURCE_DATE_EPOCH`**：见第八节（2）。一行环境变量即可，但要再打一次包 + 重验。
* **`tools/verify_release.ps1` 的测试仍跑在全局开发环境**：其 `Invoke-Python` 函数里写死了
  `"python"`（裸名字，与本次修的 pyinstaller 是同一类问题）：

  ```powershell
  function Invoke-Python([string]$Name, [string]$Script) {
      return Invoke-Native $Name "python" @($Script)
  }
  ```

  也就是说"给发布物背书的那套测试"跑在**另一个环境**里。本轮已实测 14 个相关脚本在
  干净 venv 下**全部通过**（第七节），所以改成用 `-CleanVenv` 的解释器是可行的；
  但它会改变发布验证脚本的行为，且完整 27 项套件（含 UI 探针与像素校验）本轮没跑，
  因此**只报告不擅改**。
* **未跑完整 `verify_release.ps1` 27 项**：与前几轮口径一致（UI 探针/像素校验需在真机桌面会话下跑）。
* **未改 `requirements.txt`**：`check_requirements.py` 14/14 证明不需要补声明。
* **未改 `docs\THIRD_PARTY_LICENSES.md` 内容**：重生成后无变化（仅 SBOM 的时间戳变了）。
