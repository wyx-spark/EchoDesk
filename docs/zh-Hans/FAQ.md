# EchoDesk 常见问题与故障排除（FAQ）

适用版本：v0.2.2
English version: [`docs/en/FAQ.md`](../en/FAQ.md)（本文为英文版的中文参考译本，如两者有歧义，**以英文版为准**）。

**平台**：EchoDesk 支持 **Windows、macOS、Linux** 三平台。其中**两项能力是 Windows 专属**——通过 COM 读取
WPS/Office 的**加密文档**（含旧版 `.doc` / `.xls`），以及企业内网浏览器自动化。其余功能（对话与流式输出、
文件解析、本地检索、Agent、MCP、技能、模型管理）三平台表现一致。这两处例外在「四、文件与长文档」与
「五、自动化（浏览器）」里会再说明一次。

**本文里的路径怎么写**：程序目录内部的路径统一用正斜杠（`app/backend/config.json`）——macOS 与 Linux 上
就是这样显示的，Windows 上同一条路径写作 `app\backend\config.json`。真正因平台而不同的只有**用户数据目录**
（会话文件、`ui_state.json`、`snippets.json`、`results/`），因为各平台有各自的惯例：

```
# Windows —— 程序目录本身（便携版就是 app/ 所在的外层目录）；
#            若就装在 %APPDATA%\EchoDesk 下，那它就是 %APPDATA%\EchoDesk
C:\Users\<用户名>\EchoDesk-v0.2.2\
%APPDATA%\EchoDesk\

# macOS
~/Library/Application Support/EchoDesk/

# Linux（未设置 XDG_DATA_HOME 时为 ~/.local/share/EchoDesk/）
$XDG_DATA_HOME/EchoDesk/
```

macOS 与 Linux 上程序本体就是解压出来的压缩包，用 `./start.sh` 启动
（解压时丢了可执行位就先执行一次 `chmod +x start.sh app/EchoDesk`）；Windows 用安装程序或便携版 zip。
`ECHODESK_DATA` 在三平台都能覆盖数据目录；完整的安装与启动步骤用户手册覆盖安装启动、日常问答、长文档处理、批量自动化与技能使用，并给出没有图形环境时的替代做法

## 一、快速上手

| 我想做的事 | 怎么做 |
| --- | --- |
| 启动程序 | **Windows**：安装程序装的用开始菜单（或桌面）快捷方式；zip 免安装版双击程序文件夹内的「Start-EchoDesk-v0.2.2.lnk」（没有就先运行一次 `install-complete.bat`）。**macOS / Linux**：发布物是解压即可用的压缩包，`cd` 进解压出来的目录后执行 `./start.sh`（可执行位丢了就先 `chmod +x start.sh app/EchoDesk`） |
| 查看全部指令 | 在输入框输入 `/help` |
| 让 AI 读一份文档 | 把文件拖进窗口，或用 `/file <路径>`，例如 `/file "C:\My Documents\采购合同 2026.docx"`（Windows）、`/file "/Users/<用户名>/Documents/采购合同-2026.docx"`（macOS）、`/file "/home/<用户名>/docs/采购合同-2026.docx"`（Linux） |
| 让 AI 自己算数、查已上传的文件 | 切到智能体模式：`/mode agent`、`/mode 3` 或 `/agent on`，模型会自己决定调哪个工具（见「三、对话模式、Agent 与 MCP」） |

| 超长文档（合同/报告） | 直接上传即可：超出上下文窗口会自动分段摘要；也可 `/summarize` 手动触发 |
| 换个模型 | `/model list` 看本地模型，`/model 名称` 切换 |

| 自定义助手角色 | `/prompt 你是财务顾问`（优先级最高，会盖住模式与任务模板；`/prompt reset` 恢复） |
| 切换生成参数档位 | `/preset light`、`/preset balanced`、`/preset quality` 三档一键切换 |
| 上下文快满了 | `/compact` 立刻压缩上下文腾出空间（也可点状态区的「🗜 压缩上下文」） |

| 打开设置 | 点工具栏 ⚙ 或按 `Ctrl+,` |
| 打开技能市场 | `Ctrl+M`（或设置窗口 → 技能市场） |
| 退出 | `/exit`（10 秒倒计时后自动关闭） |

**快捷键一览**：`Ctrl+Enter` 发送 · `Enter`/`Shift+Enter` 换行 · `Esc` 停止生成/关闭弹层 ·
`Ctrl+L` 清空对话 · `Ctrl+O` 上传文件 · `Ctrl+Shift+C` 复制全部对话 ·
`Ctrl+加/减/0` 调整字号 · `Ctrl+T` 切换浅色/深色 · `Ctrl+,` 设置 · `Ctrl+M` 技能市场。

**提问太模糊时它会先给方向**：像「这个怎么办」这类既没有明确对象、又没有文件上下文的提问，
程序会列出 2~3 种可能的意思并各给一句做法，你回一个编号即可，而不是硬答、也不是要求你先说清
对象与输出形式（已经聊了几轮或上传了文件时不会再触发）。想要更贴合你这句话的方向，
可以套用需求澄清模板 `/task guide`；不想要这一步可在 `app/backend/config.json` 里把
`clarify_vague` 改为 `false`。

## 二、启动与模型

### 双击快捷方式没反应 / 提示"后端启动失败"
1. 先看 `app/backend/backend_crash.log`（后端每次启动都会创建该文件，**有内容**才代表崩过，
   空文件是正常的）——里面会有完整的 Python 堆栈。macOS/Linux 上同样先看这个文件：
   那边是用 `./start.sh` 启动的，启动失败时终端里也会打印信息。
2. 把日志内容反馈给我们即可定位。

### 提示"本地未找到所需模型" / 一个模型都没有
v0.2.1 起这种情况下程序**照常运行**——不退出、不阻塞、也不会背着你下载任何东西。
状态栏显示「无模型」，对话框给出引导，不依赖推理的功能全部可用
（文件解析、设置、技能市场、模型市场、会话历史）。三种拿到模型的方式，都不需要重启程序：
1. **设置 → 模型 → 模型市场**搜索并下载。列表显示**全部** GGUF 仓库（不按硬件过滤隐藏），
   适合本机的条目标有「(推荐)」，`config.json` 里配置的默认模型所在仓库固定在结果上方
   （单独钉住、不计入分页条数）。下载完成会**热加载**。
2. **把 `.gguf` 放进 `app/backend/models/`**，点「重新扫描模型文件夹」；
   只扫描到一个模型时会自动加载。
3. **在「本地模型库」里点「加载」**，加载已下载的模型。
也可以改 `app/backend/config.json` 的 `model_repo` / `model_path` / `hf_endpoint` 指向自己的模型。

### 模型市场以前会隐藏模型，现在改了什么
现在不再隐藏任何模型。数据来源有三类：远端搜索结果、配置的默认模型、本地已下载模型。
硬件探测只用于给适合本机的条目**加标记**，绝不据此过滤。
默认模型所在仓库**单独钉在结果列表上方**并标注来源，因此它不可能"压根不出现"。

### 搜索 GGUF 有几万条，为什么只看到一部分
程序会自己按页把结果全部取回来，但单次加载有条数 / 请求次数 / 耗时三个上限（防止关键词过宽时
把网络和内存拖垮）。达到上限时状态行会写明"已加载 N 条，还有更多"，并出现「继续加载」按钮，
点它接着取。已经取回的结果会缓存到本地，同一关键词再次搜索直接命中缓存，"刷新"才会重新联网。

### 列表里的下载量和我在 Hugging Face 网页上看到的对不上
网页默认显示的是**最近 30 天下载量**，EchoDesk 列表显示的是**历史总下载量**（排序也按它）。
两者本来就不是一个数——一个老模型可能历史总量很高、最近 30 天却几乎没人下载。
如果某条结果接口里没有历史总量字段，界面会回退成"最近 30 天"并**逐条标注**，不会显示成 0。

### 筛选之后分页按钮 / 翻页行为
本地筛选（筛选词与参数量、量化、时间等多选条件）只在**已经取回的结果**范围内生效，
不会重新联网；筛选一变，页码会回到第 1 页。翻页、切排序维度时筛选条件保持不变。
同一个维度内勾多项是"或"（比如"≤1B"或"1–3B"），不同维度之间是"且"。
本地筛完一条都没有时，会出现「重新搜索远端」的入口——那是提示你可能要去远端换关键词，
而不是程序坏了。

### 加载模型失败了
程序会保持无模型状态并说明原因（文件损坏 / 格式不支持 / 内存不足）。可以换更小的量化版本，
或确认这个 `.gguf` 是完整的 GGUF 文件。不需要重启：处理好文件后再点一次「加载」
（或「重新扫描模型文件夹」）即可。

### 想换模型但不想下载
1. 把 `.gguf` 文件放进 `app/backend/models/`；
2. `/model list` 确认已识别；
3. `/model 文件名或前缀` 切换。
   若在 `config.json` 的 `models` 里配好档案（别名 → path/repo/context_length/temperature），
   就能用 `/model 别名` 一键切换并自动套用它的上下文长度与温度。

### 自定义档位会不会删我的模型文件
不会。**删除档位只删掉"这一档"的登记，磁盘上的 `.gguf` 文件一个都不动**——
档位只是"我常用这一档"的记录，删文件在模型库里另有入口（带确认）。
另外，**正在使用的档位会拒绝删除**，程序会提示你先切到别的档位再删。

档位现在可以在设置窗口「模型」页新增 / 修改 / 删除（别名、模型文件名或路径、仓库、
上下文长度、温度、备注），不必再手改 `config.json`。同一页的推理参数面板同样如此：
温度、top_p、重复惩罚、最大生成 token 四条滑块加「保存」即可写入并回读真实生效值。

### 回答很慢
- 上下文窗口越大、KV Cache 占用越高、速度越慢。`/status` 会显示当前窗口与 KV Cache 估算。
- 生成速度低于约 3 字/秒时，回复末尾会自动给出提示（可在 `config.json` 里关掉 `speed_hint`）。
- 可调小 `config.json` 的 `context_length`（默认 8192），或调大 `n_threads`，
  或换更小的量化模型（如 Q4_K_M）。
- 推理模型（Qwen3 thinking、DeepSeek-R1）会先"想"再答，思考本身也要花时间：界面上
  「🧠 思考过程」在动就说明它在正常产出，不是在卡死。

### 模型输出了 `<think>…</think>` 一大段思考，怎么分开了
这是推理模型的正常行为，EchoDesk 已经把两者分开（模型思考内容分离）：
- 答案区**只显示最终答案**；思考内容放在答案上方的「🧠 思考过程」折叠区里，默认收起，
  点标题栏展开/收起；
- 流式生成时思考区先自动展开示意，**答案开始输出时自动收起**；
- 模型没有思考内容时不会出现空的折叠区；
- **思考内容不参与上下文**（不会发给模型），但**会随会话保存**，重新打开还在（收起状态）；
- 复制按钮与 `Ctrl+Shift+C` 只复制答案；要复制思考内容请在展开区里拖选，
  或用 `/save` 导出（导出件里思考是可折叠块）。

### 模型只输出了一堆思考、没有给答案
界面会在答案区提示"模型只输出了思考内容"（思考标签没有闭合时）。
几乎都是**生成长度上限用完**了——思考把 token 预算吃光，答案还没开始写。处理办法：
- 用 `/preset quality` 切到高质量档（生成长度 2048，`/preset balanced` 是 1024）；
- 或在 `config.json` 里调大 `max_tokens`（默认 1024）；
- 或把问题问得更具体（问题越模糊，模型越想）；
- 小模型（0.5B~1.5B）的思考质量本身不稳定，换个更大的量化版本通常更划算。

### 想让 EchoDesk 开机自动启动
把「Start-EchoDesk-v0.2.2.lnk」复制到系统「启动」文件夹（`Win+R` → 输入 `shell:startup`）即可。
配置项 `automation.start_with_windows` **尚未实现**：程序目前不会读取它，写成 `true` 也不会开机自启，
请用上面的快捷方式办法（定时自动化要求程序在运行）。

这条路径**从名字到机制都是 Windows 专属**（`.lnk` 快捷方式 + `shell:startup` 文件夹）。
macOS 与 Linux 上本版**没有内置任何开机自启机制**：需要你自己用 `./start.sh` 启动，
或接进桌面环境自带的自启动能力（macOS 的「登录项」、Linux 桌面环境的自启动项或 systemd 用户单元）
——这些入口 EchoDesk 自己不会创建。

## 三、对话模式、Agent 与 MCP

### 六个模式怎么少了一半
没有少，只是不再占模式位。现在只有 **3 个模式**（`chat` 通用对话 / `contract` 条款审查 /
`agent` 智能体），被合并掉的 `summary` / `translate` / `code` / `creative` / `guide`
改由 `/task` 任务模板承担（`general` 只是改名叫 `chat`）。

**旧写法仍然可用**：`/mode summary` 会自动切到 chat 并套上 `/task summary`，
温度也沿用旧预设（summary 0.4 / translate 0.3 / code 0.2 / creative 0.9 / guide 0.6），
回复里会说明"已并入其它模式、已自动套用 /task xxx"；不想要模板时用 `/task off` 取消。
**旧编号不再自动迁移**：编号在两套编号体系里会指不同东西（旧的 `/mode 2` 是 summary，
新的 `/mode 2` 是 contract），所以 `/mode 4` 这类旧编号会明确报错并告诉你改用哪个模板，
而不是"猜着切"。想无歧义就直接写模式名（`/mode summary`），或先 `/mode chat` 再 `/task code`。
完整说明见用户手册的「对话模式：3 个模式，旧写法照旧可用」一节；任务模板也已从 6 个增加到 8 个
（新增 `creative` 创意写作与 `guide` 需求澄清）。

### 为什么 Agent 不会联网搜索
因为**联网搜索属于敏感工具，默认关闭**：它会把你的关键词发到互联网，所以需要你显式授权——
`/agent allow web_search`（写进 `config.json`，长期生效），设置窗口的「智能体」页也能勾选。
同理，读取本机任意文本文件的 `file_read` 也默认关闭（用 `/agent allow file_read` 打开）。

没被授权的工具**不会静默失败**：对话里会显示 🔒 与"未启用、怎么开"，模型据此改用已有信息作答。
安全工具（计算 `calc`、日期 `date`、单位换算 `convert`、在已上传文件里检索 `doc_search`
与取摘要 `doc_summary`）不需要授权，默认就能用。`/agent list` 可看全部工具的授权状态，
`/agent steps <1-8>` 调整步数上限（默认 4）。

### MCP 会把我的数据传出去吗
**取决于你配置的那个 server 进程，而不是 EchoDesk 本身。**

- EchoDesk 自带的是 stdio 客户端，**不会自动发现、也不会自动连接**任何地址；
  默认 `mcp.enabled` 就是 `false`、`auto_connect` 也是 `false`，不配置就不会有任何外部进程被拉起。
- MCP Server 是你自己配的命令（`command` + `args`），它的行为不受 EchoDesk 控制，
  所以它的工具**一律按敏感工具处理**，必须先 `/agent allow mcp__<server>__<tool>` 才能调用。
- 默认**不透传**父进程的环境变量（密钥不会顺手交给第三方进程）；要透传就在那个 server 的
  `passthrough_env` 里点名。

也就是说：**"数据不出本机"在默认配置下依然成立**；一旦你自己接了 server，
数据边界就由那个进程决定——请只接入你信任的 server。

## 四、文件与长文档

### 支持哪些格式
`.docx` `.xlsx` `.xlsm` `.xls` `.pptx` `.pdf` `.txt` `.md` `.csv` 等纯文本类。
- `.doc` / `.ppt`（旧版二进制）需要本机装有 WPS/Office（走 COM 读取，顺带能读**加密文档**）；
  否则请先另存为 `.docx` / `.pptx`。**这条路径仅 Windows 可用**：它依赖的 COM 接口在 macOS/Linux 上
  不存在，那边会明确提示「该能力仅 Windows 提供」——这是刻意的，**不是**解析失败、**也不是**依赖缺失，
  更不会让你去装 WPS。替代做法：
  (a) 在**一台 Windows 机器**上用 WPS/Office 另存为未加密文件或 `.docx`，再把这份副本上传到这里；
  (b) 通过 **MCP Server** 或**技能**调用外部转换工具，让它返回纯文本；
  (c) 安装一个**自带该格式解析器的技能**，让这份文档根本不走 Windows 专属那条路。
- 扫描件 PDF 没有文本层，解析结果会为空——这类文件需要 OCR，v0.2.0 未内置。

### 为什么长文档的回答没有引用原文细节
超过上下文窗口一定比例（默认 50%）时，EchoDesk 会先分段摘要再注入，**摘要会丢掉细节**。
此时：
- 摘要末尾带有「原文指针」（各段对应的原文字符区间），可据此缩小提问范围；
- 想基于全文回答，可以调大 `config.json` 的 `context_length` 与 `summarize.trigger_ratio`，
  或把文档拆成几段分别上传。

### 长文档提问为什么只看到几段而不是全文
因为长文档**不会把全文塞进上下文**，而是"摘要给全局 + 检索给细节"：

- **短文档（全文能进窗口）**：不检索，直接注入全文——材料够短时全文最准，检索只会丢信息；
- **长文档（已落盘或已生成摘要）**：注入摘要 + 检索到的相关片段，片段排在文件块之前
  （默认 `top_k` 4 段、总长上限 2400 字符）。

注入的每段都带位置，形如 `采购合同.docx（字符 210-480）`，并要求模型用 `[编号]` 标注依据，
所以你可以拿着文件名与字符区间回原文核对。想看更多片段就调大 `config.json` 的
`retrieval.top_k` 与 `retrieval.max_context_chars`；完全不想要检索，把 `retrieval.enabled`
改成 `false` 即可。

### 上传后模型说"没有看到文件"
提问时请**提及文件**（例如「根据这份合同…」「文档里第 3 条是什么」）。
为了省上下文，未提及时只注入文件名指针，不注入内容。

### 怎么知道分段摘要还在跑、而不是卡死了
v0.2.1 起长文档摘要会在对话框里实时显示进度：当前阶段（分段 / 逐段摘要 / 合并）、
正在处理第几段共几段、整篇与当前段已耗时、以及当前段已生成多少文字。
因为每段都走流式生成，最多几秒就会有一条状态更新 —— "长时间毫无输出"在设计上已经不会出现；
只是**偏慢**的段会被标注为偏慢并继续跑，不会被当成错误。
点停止会**立刻**中止当前段；原文保留在上下文中，**不会注入半份摘要**，可以直接用 `/summarize` 重试。
若某一段确实失败，该段会退回原文截断兜底，并在结果里如实说明。
超时可在 `config.json` 的 `summarize` 里配置：`chunk_timeout_seconds`（0 = 不限）与
`chunk_timeout_action`（`skip` / `retry` / `abort`）。

### 同一份文件再上传一次，还要重新摘要吗
不用。**分段摘要结果会被缓存**（按「文件指纹 + 摘要参数」做键），同一文件第二次上传直接复用，
不重新计算；文件内容改动（大小或修改时间变化）后缓存自动失效。
想清空缓存，删除 `app/backend/summary_cache.json` 即可（可读 JSON，也可直接查看）；
不想用缓存可在 `app/backend/config.json` 里把 `summary_cache` 改为 `false`。

### 长文档摘要为什么比以前快了很多
v0.2.1 优化已知问题-2 起，每一段在送进模型之前会先做**抽取式预筛**：用 TextRank 加"稀有度"
统计选出最重要的句子，模型只看抽出来的部分。这一步**不需要模型、毫秒级完成**，
实测 47KB 文档的把送入模型的内容从 5 万字符降到 1.8 万字符（少 64%），
所以分段摘要的总耗时明显下降。

它是有损的：抽取的最小单位是整句，极短句很多的文档（合同条款那种）可能丢掉部分细节。
想完全不丢可以关掉或在 `config.json` 的 `summarize` 里调大 `extractive_ratio`
（默认 0.35；设 1.0 等于不抽取），也可以把 `extractive` 改为 `false`。
日志里会写明本次预筛了多少段、省下多少字符（"抽取式预筛 N/M 段生效，送模型 X → Y 字符"）。

### 一次能上传多个文件吗
可以。文件对话框支持 Ctrl / Shift 多选与框选，也可以一次拖入多个文件。
每份文件会**单独显示状态**（`⏳ [3/8] 合同.docx …` → `✅` 或 `❌`），
**单个失败不影响其他**，结束时统一提示"已加载 N 个文件"。
一次最多 10 个文件、总量上限 60MB，超过会先问一次；超出的文件不处理并会告知。

提问时**全部文件都会注入**（每份带文件名标签），总量受 `config.json` 的
`files.total_chars`（默认 60000 字符）约束；装不下的会从**最早上传的**开始舍弃，
并在回答前明确告诉你哪几份没注入 —— 不会静默丢掉。
文件名列表可以在 `/status` 里看到；用 `/file` 可以逐个加载或单独移除。

### 打开文件时提示"路径不存在"，但文件明明在
路径里有空格。指令参数需要用引号包起来：

```
# Windows
/file "C:\My Documents\采购合同 2026.docx"

# macOS
/file "/Users/<用户名>/Documents/采购合同 2026.docx"

# Linux
/file "/home/<用户名>/docs/采购合同 2026.docx"
```

（加引号这条规则三平台一致。`/file` 会原样使用你写的参数，所以路径要写完整——这里的 `~` **不会**被展开；
macOS/Linux 上的绝对路径从 `/Users/<用户名>/` 或 `/home/<用户名>/` 开始。
v0.2.1 优化已知问题-2 之前，含空格的路径会被当成多个参数，所以一直加载失败；
界面上点"上传文件"按钮或直接拖拽没有这个问题。）

### 为什么会话重新打开后，文件名还在但没有内容
会话文件（`session.json`）**不保存文件正文**（正文有几万到几十万字，存进去会让会话文件
膨胀到几十 MB，而正文随时可以从原文件重新解析），只保存文件名、体积与已生成的分段摘要。
所以恢复会话后：已有摘要的文件仍能基于摘要回答；没有摘要的文件会提示你重新上传。

### 开了联网搜索，为什么回答里看不到搜索结果的痕迹
v0.2.1 优化已知问题-2 修掉了三件事，如果仍然看不到，可以按这个顺序查：

1. **搜索没拿到结果**：现在会**明确告诉你**（区分"搜索失败"与"没有结果"），
   不会再像以前那样静默继续。
2. **搜索结果没被注入**：搜索开关若为关闭状态（状态区显示 `🔍 搜索：关`），
   提问时不会搜索；用 `/search on` 打开。
3. **模型忽略了结果**：搜索结果的注入格式已改成编号列表并要求引用编号，
   小模型仍可能不完全遵守 —— 提问时点名"根据第 1 条结果"会明显提高引用率。

## 五、自动化（浏览器）

> **⚠️ 浏览器自动化仅 Windows 可用。** 它通过 Playwright 驱动本机的 Edge，有头运行并使用复用的登录态。
> **macOS 与 Linux 上不提供该功能**：自动化页面不会出现，请求该能力时得到的回答是
> `Windows-only capability (this is not a missing dependency)`（仅 Windows 提供该能力，不是依赖缺失问题）
> ——这是刻意的：它不是装坏了，也不是缺个包。替代做法：用 **MCP Server** 或**技能**完成同一套流程，
> 或**在一台 Windows 机器上跑完之后把结果目录拷过来**。下面各条描述的是 Windows 上的行为，
> 因为只有那个平台有这套功能。

### 能用什么浏览器
必须已安装 **Microsoft Edge**（Playwright 通过 `channel=msedge` 驱动它，有头模式运行，
你能看到浏览器在操作）。构建脚本会检查 Edge 是否存在。

这里指的是**Windows 上**的 Edge：macOS 与 Linux 上没有可配置的自动化页面，这一节的内容对那两个平台不适用
（见上面的提醒）。

### 开启自动化时提示需要勾选安全协议
这是设计如此：**安全协议未勾选时自动化开关会被后端强制关闭**，
并且协议版本与你的同意时间会记入 `app/backend/automation_log.jsonl` 以便审计。

### 填了网址但"测试选择器"匹配不到元素
1. 先用浏览器 F12 确认选择器能选中目标（CSS 直接粘贴，XPath 以 `//` 开头）；
2. 页面若是动态加载，可稍等再点测试；
3. 元素在 `<iframe>` 内或 Shadow DOM 中时，定位会尝试穿透，但不保证 100% 成功——
   此时改用更外层的选择器。

### 出现验证码或二次验证
程序会暂停并提示「检测到验证码/二次验证，请手动完成」，
你在弹出的浏览器窗口里手动完成后，程序会继续（默认最多等 180 秒；
可在 `config.json` 的 `automation.manual_login_wait_seconds` 调整）。

### 怎么停止
设置窗口里点「⏹ 停止自动化」，或回到主窗口按 `Esc` / 点 ⏹。
已下载的临时文件会被清理，浏览器会关闭。

### 下载的文件去哪了
每个任务下载的原始文件会**移动到该任务的结果目录**里，与生成的审核意见放在一起：

```
results/2026-09-23/合同审查/     ← 顶层文件夹名、日期、任务名称都可配置
├─ 合同正文.pdf                       ← 该轮下载的原始文件（重名自动加序号）
├─ result.txt                           ← 摘录 + 审核意见（纯文本，无 Markdown 标记）
└─ failure-screenshot-task2-20260923_101010.png  ← 仅在任务失败时生成
```

目录里的分隔符跟着运行平台走（Windows 是 `\`，macOS/Linux 是 `/`），文件夹名三平台一致。

下载过程中的临时副本保存在系统临时目录的专用子目录，处理完即清理。
若把「保存结果到本地文件」关掉，就不写 `result.txt` 与截图，只把结果输出到日志。
「保存位置」留空时，结果根目录 = **用户数据目录** + 顶层文件夹名，因此跟着平台走
（Windows 上就是程序目录所在的**外层**文件夹 `EchoDesk-v0.2.2/`，不在 `app/` 里）：

```
# Windows
%APPDATA%\EchoDesk\results\
C:\Users\<用户名>\EchoDesk-v0.2.2\results\      ← 解压在哪儿，就是那儿的这个目录

# macOS
~/Library/Application Support/EchoDesk/results/

# Linux（未设置 XDG_DATA_HOME 时为 ~/.local/share/EchoDesk/results/）
$XDG_DATA_HOME/EchoDesk/results/
```

想让用户数据整体换位置（含 `ui_state.json`、`snippets.json`），可以设置环境变量 `ECHODESK_DATA`。
保存位置、顶层文件夹名与任务名称的填法自动化指南逐字段说明任务链接、登录判定、翻页与结果目录的填写方法，并提供选择器可视化选取

### 登录态
第一次需要手动登录一次；程序会把 Cookie/localStorage 存进 `app/backend/browser_state.json`，
下次自动复用。删除该文件即可退出所有登录态。

## 六、技能市场

### 搜不到技能 / 列表为空
技能市场的技能必须在其 GitHub 仓库上打 **topic `echodesk-plugin`**。
没有结果通常意味着该 topic 下暂时没有仓库，而不是程序故障。
可以先点「刷新」看缓存快照，或用关键词搜索。

### 提示"离线：展示本地缓存快照"
GitHub 匿名 API 限流（每小时 60 次）或网络不可达。解决办法：
- 在 `app/backend/config.json` 的 `marketplace.github_token` 填入一个 GitHub Token（可把限额提高到 5000 次/小时）；
- 或稍后重试；程序会继续使用本地缓存，不会因此报错。

### 安装按钮是灰的
卡片显示「⚠ 未验证」时按钮置灰——表示该仓库根目录缺少 `skill.json` 或其中没有
`echodesk.bundle` 字段。这类技能来源不可信，默认不允许安装。

### 安装会执行第三方代码吗
**不会自动执行 `prepare` 脚本**。安装流程只做：下载源码 → 校验 `skill.json` →
复制到 `app/backend/skills/` → 登记到 `app/backend/skills_registry.json`。
若技能声明了 `prepare` 脚本或依赖，会在提示里列出，由你自己决定是否手动处理。
即使将来执行 prepare，也会先移除所有名称含 `KEY`/`SECRET`/`TOKEN`/`PASSWORD` 的环境变量。

### 卸载不干净
卸载会：移除注册表条目 → 删除技能目录 → 回读注册表确认。若仍有残留，
可手动删除 `app/backend/skills/<技能id>` 并编辑 `app/backend/skills_registry.json`。

### 第一次放进第三方本地插件，会一直弹确认框吗
不会。首次加载**第三方本地插件**（放在 `app/backend/skills_dev/`）只会弹**一次汇总确认框**：
可以逐个勾选、或点「全部启用」「全部禁用」；选择会被记住，之后不再询问（拒绝过的也不会再问）。
随包示例插件（`examples/skills/`）默认启用、不询问。
设置窗口「开发者」页的**开发者模式开关双向可用**：关掉就是关掉，重启后保持关闭，
并会卸载开发插件、清空开发日志 `app/backend/skills_dev.log`。

## 七、界面

### 窗口大小/位置/主题/字号会记住吗
会，存在**用户数据目录**里的 `ui_state.json`（窗口位置与大小、字号、主题三态、emoji 显示策略、
界面语言等）。这个目录在 Windows 上就是便携版**外层**文件夹 `EchoDesk-v0.2.2/`，
macOS 上是 `~/Library/Application Support/EchoDesk/`，Linux 上是 `~/.local/share/EchoDesk/`
（本文开头有完整说明）。窗口若被还原到已拔掉的显示器上，程序会自动回退到屏幕内。
删除该文件即可重置（含"首次引导已读"标记）。

### 主题只有"深色开关"吗
不是，现在是**三态**：跟随系统 / 浅色 / 深色，在设置窗口「常规」页选择。
选「跟随系统」时跟随操作系统的外观设置（Windows 上就是应用模式，macOS 与 Linux 上是系统的外观/主题设置），
你在系统里切换浅色/深色，界面会立刻跟着变。
快捷键 `Ctrl+T` 在浅色与深色之间切换，`/darkmode on|off|auto` 也可以直接指定。

### 界面出现 `[OK]` / `[!]` 这样的纯文本标记，是坏了吗
不是。设置窗口「常规」页的 **emoji 显示**同样有三态：自动 / 始终显示 / 不使用。
选「自动」时，如果本机缺少 emoji 字体（精简版系统或被组策略裁掉字体的环境），
界面会自动改用纯文本标记而不是显示方块；想恢复彩色图标可装回 emoji 字体后重启。

### 状态区里的「⚠️ 能力提示 N」是什么
它是**模型能力边界**的提示按钮：只有真的触到边界时（可用窗口明显小于训练窗口、
实测生成速度过低、KV Cache 估算超过本机内存的一半等）才会出现，点开逐条列出原因与可采取的动作
（例如调小 `context_length`、调大 `n_threads`、换更小的量化模型）。
状态区同时还会显示模型能力项（参数量 · 量化 · 可用窗口 · 实测生成速度），点它可以打开
「设置 → 模型」看完整能力与推荐配置。

### 消息里的滚轮滚不动
已禁用消息控件内部滚动，滚轮统一滚动整个对话列表。`Ctrl+滚轮` 调节字号。

### 想反馈问题
请附上：所在平台（Windows / macOS / Linux）及其版本、`app/backend/backend_crash.log`（若有内容）、
`app/backend/config.json`、`/status` 的输出，以及能复现问题的操作步骤。
