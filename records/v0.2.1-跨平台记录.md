# v0.2.1 跨平台 记录

任务书：`prompts/EchoDesk-v0.2.1跨平台.md`（六项任务）
前置轮次：`records/v0.2.1-能力扩展-1记录.md`、`records/v0.2.1-优化已知问题-2记录.md`

这一轮的性质是**架构级改动**：把"只在 Windows 上能跑"这件事从架构上改掉。
任务书本身规定了方法（原型优先、逐模块迁移、降级要显式），因此记录按
**本机条件与限制 → 逐项审计 → 复用/重写取舍 → 实现 → 证据 → 未完成项**来写，
并且对"哪些结论有运行级证据、哪些只有构建级证据"逐条标注。

---

## 〇、本机条件（决定了本轮能做到什么程度）

| 条件 | 实测 | 对交付的影响 |
| :--- | :--- | :--- |
| 操作系统 | Windows（10.0.26300），**无 WSL、无 Docker、无 macOS** | 真实运行只能覆盖 Windows |
| .NET SDK | 10.0.103 | Avalonia 与 WPF 都能构建 |
| 非 Windows 运行环境 | 不存在 | 非 Windows 的**运行级**证据只能由 CI 矩阵产出 |
| 交叉发布 | `dotnet publish -r linux-x64 / osx-arm64` 可用并已实测成功 | 只能证明"能构建出目标平台产物"，不等于能在目标平台运行 |
| PyInstaller | 6.x，**不能交叉编译** | Linux/macOS 的后端可执行文件必须在各自平台上构建 |
| 磁盘 | 630 GB 可用 | 三平台发布物与重建发布包无压力 |

**诚实边界**：本轮交付里凡是"非 Windows 的降级行为"，证据来自**平台注入测试**
（`ECHODESK_FORCE_PLATFORM`）与**构建级交叉发布**，不是真实非 Windows 运行。
这一点在 `docs/zh-Hans/CROSS_PLATFORM.md` 与 CHANGELOG 里都写明了，不含糊。

## 一、逐项审计结论（做之前先确认"哪些已经有基础"）

### 任务一/任务二 前端原型与逐模块迁移

| 现状 | 证据 | 结论 |
| :--- | :--- | :--- |
| 前端是 WPF，目标框架 `net10.0-windows` | `frontend/EchoDesk.csproj` | 带 `-windows` 后缀就**无法**在 Linux/macOS 上编译，必须新增工程而不是改后缀 |
| 前端与后端之间只有一条 JSON 行协议 | `frontend/Services/BackendService.cs`（685 行） | 协议层与平台无关，**可以照搬**；界面层必须重写 |
| 富文本依赖 `FlowDocument` | `frontend/Utilities/MarkdownRenderer.cs`（26 KB） | Avalonia 没有 FlowDocument，必须换渲染结构（这是"必须重写"的核心一处） |
| 主题靠两套手写色板 + `DynamicResource` | `frontend/Resources/Theme.{Light,Dark}.xaml` | Avalonia 用 `FluentTheme` + `ThemeVariant`，实现方式必须重写 |
| 界面语言包是按模块拆分的 JSON | `frontend/Resources/Lang/*.json` | 可以**被两个前端共用**（通过 csproj 链接内嵌，保持单一来源） |

### 任务三 后端多平台

| 现状 | 证据 | 结论 |
| :--- | :--- | :--- |
| `import win32com.client as win32` 在模块顶层 | `backend/file_parser.py:32`（改前） | **这是最硬的阻断点**：Linux/macOS 上后端启动即 ImportError 崩，必须先改 |
| `requirements.txt` 无条件依赖 `pywin32` | `backend/requirements.txt`（改前） | 非 Windows 上整条依赖链装不上，必须加环境标记 |
| 平台判断散落在 `os.name == "nt"` | `emoji.py`、`i18n.py`、`model_profile.py` | 需要一处收口（新增 `platform_support.py`），否则前端对不上 |
| 用户数据目录用"发布物外层目录"规则 | `backend/config.py:25` | Windows 行为要**保持不变**（不制造回归）；非 Windows 才按 XDG/Application Support |
| 打包用 PyInstaller onedir + `backend/EchoBackend.spec` | `tools/build_release.ps1` | spec 里有 Windows 专属项（`.exe`、版本资源、`.ico`），要按平台分支 |

### 任务四 打包

| 现状 | 证据 | 结论 |
| :--- | :--- | :--- |
| Windows 打包脚本齐备（干净 venv → PyInstaller → dotnet publish → Inno Setup） | `tools/build_release.ps1` | Windows 路径**复用不动**，只补跨平台路径 |
| 没有非 Windows 打包能力 | 无 | 新增 `tools/pack_crossplatform.py`（脚本本身跨平台） |
| CI 只有 Windows runner | `.github/workflows/ci.yml` | 新增三平台矩阵（构建 + 发布 + 平台测试 + 无窗口自检） |

### 任务五 降级策略

| 现状 | 证据 | 结论 |
| :--- | :--- | :--- |
| WPS COM 读取路径失败时回退内置解析器 | `file_parser.parse_file_with_wps` | 回退已有，但**文案**在非 Windows 上是误导（"请安装 WPS/Office 后重试"），必须按平台分文案 |
| 自动化没有平台前置检查 | `automation.AutomationEngine.validate` | 非 Windows 上会报"没装 Playwright"，把平台限制说成依赖缺失，必须改 |
| 其余能力纯 Python | 检索 / Agent / MCP / 技能 / 模型管理 | 无平台耦合，保持三平台一致 |

### 任务六 多语言与文档

| 现状 | 证据 | 结论 |
| :--- | :--- | :--- |
| 双语语言包齐全且有一致性门禁 | `tools/check_lang.py`（后端 1051 键、前端 998 键） | 新增文案必须同时进两套语言包，门禁会拦住漏翻 |
| 文档按 `docs/<locale>/` 成对存在 | `docs/zh-Hans/`、`docs/en/` | 新增平台文档要成对添加，`check_lang.py` 会检查一一对应 |

## 二、与任务书的偏差（逐项交代）

| 任务书要求 | 实际做法 | 原因 |
| :--- | :--- | :--- |
| 任务二"逐模块迁移（主窗口 → 设置 → 面板）" | 本轮**只迁移主窗口**，设置与面板仍是 WPF | 任务书同时要求"先原型、验证后再迁移"；一轮之内把 6000+ 行设置界面迁完会导致两边都无法验收。主窗口迁移的产出是**可复用的服务层**（BackendService/Loc/Emoji/AppSettings/PlatformInfo/UserPaths），后续模块是按同一模板平移 |
| 任务一"验证三平台运行" | Windows **真实运行**；Linux/macOS 只做到构建级 + 注入式降级验证 | 本机无 WSL/Docker/macOS，物理上做不到（见第〇节）。把"做不到"写清楚，而不是含糊其辞 |
| 任务四"macOS 签名与公证" | **未自动化**，命令与缺失步骤写进产物 `SIGNING.txt` | 需要 Apple 开发者证书与账号，不能进仓库、也不该由构建机持有 |
| 任务四"Linux AppImage" | 只交付 `.tar.gz` | AppImage 需要 `appimagetool` 与 AppDir/desktop 文件，属额外工具链；先给能用的归档形式，未完成项已登记 |
| 任务四"GitHub Actions 矩阵" | 矩阵已写好（三平台，含构建/发布/测试/自检） | 但**仓库尚未推送过**，因此矩阵是"已写好、待运行"，本轮无法给出 CI 绿证据 |
| 任务五"加密文档降级用通用解析器" | 加密文档走通用解析器 + 平台化文案；旧版 `.doc`/`.xls` 明确说明"仅 Windows 可读" | `.doc`/`.xls` 是二进制复合文档，通用解析器**读不了**（不是能读但读得差），说"已降级用通用解析器"会误导；改为给替代做法 |

## 三、本轮实现

### 1. 跨平台前端原型 `frontend-avalonia/EchoDesk.Avalonia/`

| 文件 | 职责 | 与 WPF 版的关系 |
| :--- | :--- | :--- |
| `EchoDesk.Avalonia.csproj` | `net10.0`（不带 `-windows`）、`AvaloniaUseCompiledBindingsByDefault`、`BuiltInComInteropSupport=false`；语言包以**链接**方式内嵌（单一来源） | 新增 |
| `Services/PlatformInfo.cs` | 平台探测（kind/name/架构/RID/可执行文件名）、能力标记、Python 解释器查找 | 新增（WPF 没有对应物） |
| `Services/BackendService.cs` | 进程管理 + JSON 协议：单请求闸门、空闲超时、流式双通道、错误分类 | **照搬** WPF 实现，仅改三处（后端定位、子进程环境、缺失后端不抛异常） |
| `Services/Loc.cs` | 语言包（磁盘目录 + 内嵌资源）、`{0}` 占位符、回退链、`LanguageChanged` 事件 | 语义等价重写（WPF 用附加属性遍历，Avalonia 用事件重建） |
| `Services/Emoji.cs` | emoji → ASCII 降级；非 Windows 默认按支持处理，Windows 仍查 `seguiemj.ttf` | 移植（表与后端 `emoji.py` 一致，`tools/check_emoji.ps1` 覆盖） |
| `Services/AppSettings.cs` / `UserPaths.cs` | 界面设置与各平台数据目录约定 | 重写（WPF 的 `ShortcutService` 是 Windows 专属） |
| `Utilities/MarkdownRenderer.cs` | Markdown → **控件树**（段落/标题/列表/引用/表格/代码块/公式块 + 行内标记） | 重写（FlowDocument → 控件树） |
| `Views/MainWindow.axaml(.cs)` | 主窗口：消息流、流式、思考折叠、上传、主题/字号/语言、平台横幅、能力清单 | 重写界面、逻辑照搬 |
| `SelfTest.cs` + `Program.cs --selftest` | 无窗口自检：平台探测 → 拉起后端 → `ready` → `platform`/`capability` 往返 | 新增 |

### 2. 后端平台化

* 新增 `backend/platform_support.py`：`kind()/name()/architecture()/rid()/report()`、
  能力清单（可用性 + 原因 + 替代做法）、`wps_com_available()/automation_available()`、
  `ECHODESK_FORCE_PLATFORM` 注入开关（**仅供测试**，报告里用 `forced` 标注）。
* `backend/main.py`：`ready` 行新增 `platform` 报告；新增 `platform` 动作。
* `backend/file_parser.py`：容错导入 `win32com`；WPS 不可用时分清"平台不支持"与"缺 pywin32"；
  旧版格式在非 Windows 上给出三条替代做法；**回归保护**（普通文本/未知扩展名路径不变）。
* `backend/automation.py`：`validate()` 最前面加平台检查，文案明确"不是依赖缺失"。
* `backend/requirements.txt`：`pywin32; sys_platform == "win32"`。
* `backend/EchoBackend.spec`：按平台分支（`.exe` 名 / 版本资源 / `.ico` / `win32com`）。

### 3. 打包与 CI

* 新增 `tools/pack_crossplatform.py`：跨平台打包（发布前端 → PyInstaller 后端 → 清理调试符号
  → 归档 → `SHA256SUMS.txt` / `manifest.json` / `SIGNING.txt`），支持 `--plan` 演练与
  `--reuse-*` 快速迭代。**实测跑通**（Windows 便携 zip，见第五节体积）。
* `.github/workflows/ci.yml`：新增 `cross-platform` 矩阵（windows/ubuntu/macos）：
  构建 → 按 RID 发布 → `test_platform.py`（真实平台分支）→ `--selftest` → 上传产物；
  后端依赖装不上时**跳过并打印原因**，不静默通过。
* `tools/verify_release.ps1`：注册 `tools/test_platform.py`。

### 4. 文档与文案

* 新增 `docs/zh-Hans/CROSS_PLATFORM.md` 与 `docs/en/CROSS_PLATFORM.md`（平台矩阵、两条降级边界、
  平台探测、目录与环境变量、打包与签名、验证证据与缺口、WPF/Avalonia 差异）。
* `README.md` / `README.zh-Hans.md`：系统要求与文档索引指向平台文档。
* `docs/{zh-Hans,en}/USER_GUIDE.md`：新增"在 Linux 或 macOS 上运行"一节（含两条降级与替代做法）。
* `CHANGELOG.md` / `CHANGELOG.zh-Hans.md`：新增本轮条目。
* 语言包：前端 `.main.json` 两语言共 17 键、后端 `platform.*` 与
  `automation.validate.platform_unsupported`（两语言），由 `check_lang.py` 与
  `artifacts/check_frontend_keys.py` 双向校验。

## 四、复用 vs 重写（任务书要求讲清楚）

| 组件 | 决策 | 原因 | 验证方式 |
| :--- | :--- | :--- | :--- |
| JSON 行协议与进程管理 | **复用**（照搬 WPF `BackendService`） | 已被 4 轮迭代验证（闸门、超时、双通道），重写只会引入新缺陷 | `--selftest` 真拉起进程走协议；打包版烟测 |
| 语言包文件 | **复用**（csproj 链接同一批 JSON） | 两个前端共用一份翻译，避免"改了一边、另一边漂移" | `check_lang.py` + 前端键探针（42/42 命中） |
| emoji 降级表 | **复用**（表原样移植） | 与后端 `emoji.py` 必须一致 | `tools/check_emoji.ps1` |
| 后端业务逻辑（对话/检索/Agent/MCP/技能/模型） | **复用**（一行未改业务逻辑） | 纯 Python，无平台耦合 | 既有测试全绿 + 新增平台测试 |
| 后端平台判断 | **重写收口**（新增 `platform_support.py`） | 原来散落多处，前端对不上就无法做一致性校验 | `tools/test_platform.py`（69 项） |
| 前端主题 | **重写**（`FluentTheme` + `ThemeVariant`） | WPF 的两套色板机制在 Avalonia 不适用 | 色板/对比度约束仍走 `check_theme.py` 口径 |
| 富文本渲染 | **重写**（FlowDocument → 控件树） | Avalonia 没有 FlowDocument | `--selftest` 启动 + 真窗口手工核对（截图见 `artifacts/ui-shots-*`） |
| 字体缩放 | **重写**（逐消息重建） | 没有"整篇一个字号"的容器 | 主窗口 A-/A+ 实测 |
| 用户数据目录 | **重写**（`UserPaths`，三方口径一致） | WPF 版是 Windows 专属实现 | `test_platform.py` 断言；与后端 `config.user_data_root()` 对齐 |

## 六、未完成项与已知限制

1. **只迁移了主窗口**：设置窗口、各功能面板（市场/技能/MCP/Agent/模型档位）仍是 WPF。
   后续按 `EchoDesk.Avalonia/Services` 已建立的模板逐模块平移（任务书要求的顺序）。
2. **非 Windows 运行级证据缺失**：真实 Linux/macOS 的启动、窗口渲染、拖拽、输入法、
   高 DPI、字体回退都未验证。CI 矩阵已写好但仓库尚未推送过，因此矩阵还没跑过一次。
3. **Linux/macOS 后端产物未产出**：PyInstaller 不能交叉编译，需在目标平台执行
   `python tools/pack_crossplatform.py` 或由 CI 完成。
4. **macOS 签名/公证未自动化**（需 Apple 证书）；未提供 `.dmg` 打包脚本；
   **Linux AppImage 未做**（只交付 `.tar.gz`）。
5. **非 Windows 图标**：`assets/EchoDesk.ico` 是 Windows 图标；macOS 需要 `.icns`，
   Linux 需要 `.png`/desktop 文件，本轮未做（macOS 上打包时按"不打图标"处理）。
6. **`pathlib` 未全面替换**：后端仍以 `os.path` 为主（功能上跨平台正确，
   任务书提到的"路径处理统一用 pathlib"只在新代码里执行）。
7. **`--selftest` 不覆盖界面**：它验证的是启动链路与协议，不渲染任何窗口；
   Avalonia 的 headless UI 测试（`Avalonia.Headless`）本轮未接入，属后续工作。
8. **自动化页面的界面级禁用**：后端已拒绝并给出原因；Avalonia 原型还没有该页面，
   因此"界面上按钮变灰 + 提示"这一层要等设置窗口迁移时一起做。
9. **平台判断漂移只在启动时校验一次**：换平台（例如在虚拟机里挂载同一数据目录）时
   需要重启才能发现不一致。
