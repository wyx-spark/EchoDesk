## 三、各功能实现方式与关键决策

### 任务一 P0-1：上下文窗口扩展与分段摘要

**实现**
- `config.context_length` 默认 4096 → **8192**，新增 `max_context`（默认 32768）作为硬上限，
  由 pydantic `model_validator` 钳制到 `[512, max_context]`，越界会打印警告而不是崩溃。
- 新增 `config.context_for_model(model_path, train_context, requested=None)`：
  实际窗口 = `min(请求值, 模型训练窗口, max_context)`，下限 512；
  `auto_context=false` 时忽略训练窗口这一项。
- 新增 `gguf_meta.py`：**只解析 GGUF 头部 KV 区**（不读张量、不加载模型）即可取得
  `{arch}.context_length`、`block_count`、`attention.head_count_kv`、`key_length` 等，
  并估算 KV Cache：`n_ctx × n_layer × n_head_kv × (key_dim + value_dim) × 2 字节`（fp16）。
  实测 0.8B 模型：训练窗口 262144、8192 窗口下 KV Cache 约 384MB。
- `LLMEngine._create()` 每次加载/重载都输出窗口日志（配置值 + 训练窗口 + KV Cache + 线程 + GPU 层）。
- 新增 `summarizer.py` 的 map-reduce 分段摘要；
  `conversation.build_messages` 在注入文件时优先使用摘要而非全文；
  新增 `/summarize` 手动触发；摘要进度打到 stderr → 前端在对话框实时显示。
- 生成速度低于 `speed_min_tps`（默认 3 字/秒）时，回复末尾追加提示与调优建议。

**关键决策**
1. **窗口取值规则**：任务书说"具体数值根据所选模型的训练上下文长度决定"。
   实现为"请求值与训练窗口取小"，而不是"直接用训练窗口"——
   因为一个训练窗口 262144 的模型若强行开满窗口，KV Cache 会到十几 GB，纯 CPU 场景不可用。
   这样既不会超限，也不会失控。
2. **不加载模型就能拿到训练窗口**：用自己写的 GGUF 头部解析器而非常规做法
   （先加载再读 `n_ctx_train()`）。理由是加载一次 0.8B 模型需要数秒并占用内存，
   而分母（窗口决策）必须在加载前确定。
3. **摘要而非截断**：任务书明确要求"而非直接截断"，因此 `file_max_chars` 提到 200000
   并在超阈值时走摘要；截断仅作为摘要失败时的兜底。
4. **摘要长度控制**：单段 `max_summary_tokens=400`、合并后 `merge_max_tokens=800`，
   超限时按 token 预算分组递归归并（深度上限 4 + 按比例截断兜底），
   避免"摘要本身又超窗口"的循环问题。

### 任务一 P0-2：下载前征询 + 快捷方式

**实现**
- 后端：`main()` 在模型缺失时**不再下载**，而是先查仓库拿到真实文件名与体积，
  输出 `{"type":"need_download","model","size","repo","current","content"}`，
  然后进入 `_await_download_decision()` 阻塞等待：收到 `action=model_download` 才下载
  （进度以 `delta` 行上报、结束时 `done`，随后继续加载+预热并最终发 `ready`）；
  收到 `exit` 或 stdin 关闭则直接退出。
- 前端：`BackendService` 新增 `NeedDownloadException` 与
  `DownloadModelAndWaitReadyAsync()`（发送下载请求后一直读到 `ready`）；
  拒绝时停止后端并在对话框给出"可手动放置模型"的指引。
- 快捷方式：`ShortcutService` 用 WScript.Shell COM（**反射调用，不引入 NuGet**）
  在程序目录创建「EchoDesk 启动.lnk」，TargetPath = 主程序、WorkingDirectory = 程序目录、
  IconLocation = 程序目录的 EchoDesk.ico；`IsValid()` 通过比对 TargetPath 与当前 exe 判断
  "移动文件夹后失效"。

**关键决策**
1. **拒绝后的行为**：任务书说"用户拒绝则后端退出，前端显示提示"。实现为后端退出、
   前端保留窗口并禁用输入 + 显示指引，而不是自动关闭窗口——用户还能读提示。
2. **拒绝记忆**：拒绝创建快捷方式后写入 `ui_state.json` 的 `ShortcutPromptDeclined`，
   下次不再询问（任务书要求）。
3. **stdout 竞争**：启动阶段 `StartAsync` 正在读同一路 stdout，
   因此下载进度必须由 `DownloadModelAndWaitReadyAsync` 在同一读取循环里处理，
   不能另起读取任务（否则两边会互相抢走对方的行）。

### 任务一 P0-3：内容可复制与界面完善

**实现**
- 纯文本消息（用户/系统）由 `TextBlock` 改为**只读 TextBox**：支持拖选与 `Ctrl+C`，
  且把内部滚动设为 `Disabled`（否则 TextBox 会吃掉滚轮，整页滚不动）。
  助手消息沿用只读 RichTextBox（Markdown 渲染）。
- 每条消息右下角复制操作条：复制（纯文本）/ Markdown（原始源码）/
  代码（存在围栏代码块时出现，`MarkdownHelper.ExtractCodeBlocks`）/ 全选。
  剪贴板被占用时重试 3 次。
- 快捷键：`Ctrl+Enter` 发送、`Esc` 停止、`Ctrl+L` 清空、`Ctrl+O` 上传、
  `Ctrl+Shift+C` 复制全部、`Ctrl+加/减/0` 字号、`Ctrl+T` 主题、`Ctrl+,` 设置、`Ctrl+M` 市场。
- 窗口状态（大小/位置/最大化）与主题、字号存入 `ui_state.json`；
  还原时用**虚拟屏幕相交判断**（`SystemParameters.VirtualScreen*`）避免还原到已拔掉的显示器。
- 状态栏拆为：运行状态 / 模型 / 模式 / 搜索 / 自动化 / 市场；
  底部新增通知条（6 秒自动隐藏），已接入模型下载完成与失败。
- 首次启动引导（`FirstRunDone` 只显示一次）。

**关键决策**
- **未做虚拟滚动**：任务书将其列为"考虑"项。对话滚动用 `StackPanel` + 外层 `ScrollViewer`，
  在千条消息量级下 WPF 仍可接受；引入虚拟化需要重写消息面板为 `ItemsControl` + 
  `VirtualizingStackPanel`，并解决"消息内 RichTextBox 高度不定"的测量问题，风险高于收益。
  已在 `docs/CHANGELOG.md` 的"已知限制"中记录。
- **高 DPI / 多显示器**：未做逐显示器 DPI 缩放以外的特殊处理，
  但窗口还原做了越界保护；主题切换为字典替换，即时生效。
- **消息折叠与历史搜索**：未实现（同上，属"考虑"项）；`/save` 导出 Markdown 可作为替代路径。

### 任务二：版权、图标与元数据

**实现**
- `tools/make_icon.py` 生成图标：圆角方形"工具砖"（本地工具）+ 左侧实心声源与
  向右扩散的三道同心回声弧（回声），主色深靛蓝 `#1B1B4D` → 深紫 `#4A1E6E` 对角渐变，
  点缀暖陶土 `#C8674A/#D9835F/#E7A183`；4 倍超采样后缩小，扁平矢量、无文字无水印。
  输出含 **16/32/48/64/128/256** 六尺寸（已逐一核对）。
- 九个字段全部写入：CompanyName / LegalCopyright / FileDescription / ProductName /
  OriginalFilename / InternalName / Comments / FileVersion / ProductVersion = 0.2.0.0。

**关键决策（重要调整）**
- **rcedit 不能作用于 PyInstaller 产物**。PyInstaller 把 PKG 归档**追加**在 PE 映像之后，
  rcedit 重建 PE 时会丢掉这段数据，后端启动即报
  `Could not load PyInstaller's embedded PKG archive`（已实测复现）。
  因此后端的版本资源与图标改由 `EchoBackend.spec` 的 `version`/`icon` 参数在**追加归档之前**写入，
  字段与前端完全一致；rcedit 只处理前端 `EchoDesk.exe`。
  这偏离了任务书"rcedit 统一处理所有可执行文件"的表述，原因是该做法对 PyInstaller 产物不成立。
- 批处理脚本必须 **CRLF**（cmd 解析 LF + label/续行会错乱，已实测失败），
  并加 `chcp 65001` 才不出现中文乱码；另加 `.gitattributes` 固定 `*.bat/*.ps1` 以 CRLF 落盘。

### 任务三：单文件夹多文件发布

**最终结构见第五节。**

**实现与关键决策**
- 前端 `dotnet publish -p:PublishSingleFile=false --self-contained`：239 个依赖 DLL 平铺根目录，
  免解压、启动更快（对齐任务书"多文件发布提升启动速度"）。
- 后端 PyInstaller **onedir**：`EchoDeskBackend.exe` + `_internal/`，依赖集中，
  便于只替换后端目录做增量更新。
- 统一命名：`EchoDesk.exe`（界面主程序）/ `EchoDeskBackend.exe`（后端）；
  构建脚本会**移除 .NET 自带的 `createdump.exe`**，保证根目录只有一个可执行文件，
  用户不会面对"该点哪个 exe"的问题；入口由构建脚本创建的「EchoDesk 启动.lnk」统一承担。
- 多语言资源目录裁剪为 `zh-Hans`/`zh-Hant`（其余与运行无关，纯减噪）。
- **体积优化（976MB → 178MB）**：这是本次最有价值的工程改进，详见任务六一节。
- 便携版与安装版区分：`tools/installer.iss` 提供 Inno Setup 模板
  （开始菜单/桌面快捷方式 + 卸载入口），与便携版内容完全一致，只是分发形态不同。
- 代码签名：`build_release.ps1 -Sign` 调用 `signtool`（支持 `-CertThumbprint`）；
  仓库内不含证书，未签名时会有 SmartScreen 提示（已在变更日志说明）。
- 杀毒误报：改 onedir + 写入完整版本资源与官方图标，可显著降低误报概率；
  进一步措施（EV 代码签名证书）需要采购，非本次范围。
- 自动更新：未实现。设计要点已在 `docs/DEVELOPER.md` 记录
  （版本清单 URL + 校验哈希 + 增量替换后端目录），留待后续版本。

### 任务四 P2：浏览器自动化

**实现**（`automation.py` + 设置窗口「自动化」Tab）
- Playwright **sync API** 驱动本机 Edge（`channel="msedge"`，实测 Edge 153 可用），
  **强制有头模式**（配置里的 `headless` 会被校验器纠正为 False，符合 4.5）。
- 引擎是生成器 `run(stop_event, on_progress)`，逐个 yield `delta`/`done`/`error` 事件，
  由 `main.py` 原样转发给前端 → 进度实时可见、`stop` 可中断（复用既有流式协议）。
- 主流程：打开列表页 → 定位任务链接（**CSS 与 XPath 双支持**）→ 逐任务进详情页 →
  按后缀筛选文件链接 → 下载到系统临时目录 → `file_parser` 解析 → 与任务指令拼接 →
  本地模型生成摘要与审核意见 → 结果回传/落盘 → **立即删除该任务临时文件** → 下一个；
  支持分页（下一页选择器）、任务去重（processed 标记文件）、失败截图并跳过、重试。
- 登录态：`storage_state` 持久化到 `browser_state.json`。
- 验证码/MFA：检测到特征时暂停并提示人工处理（默认最多等 180 秒）。
- 审计日志：JSONL，字段为 time/event/url/files（仅文件名）/result/error（截断 200 字）/
  safety_version/safety_accepted_at；脱敏函数把 `token=`/`password=`/`secret=`/`key=` 的值替换为 `***`。
- 安全前置：`enabled` 只有在 `safety_accepted` 为真时才可能为真（配置校验器强制），
  `run()` 第一步再次校验，未勾选直接 yield error 且不启动浏览器。

**关键决策与调整**
- **未自动执行第三方 `prepare` 脚本**（任务书要求"执行前移除敏感环境变量"，
  即隐含允许执行）。实现选择**不执行**并明确提示，安全优先；
  同时仍实现了 `_sanitized_env()` 供后续启用。
- **iframe / Shadow DOM**：做了穿透尝试（遍历同源 frame、`shadowRoot` 查询），
  但属简化实现。实测 Playwright 的 CSS 引擎本身已能穿透 open shadow root，
  因此该兜底很少触发；且穿透命中的元素没有句柄，只能退回"直接请求 URL"。
  复杂页面仍需用户调整选择器——已如实记入"已知限制"。
- **明确定义"线上预览"**：任务书要求"明确定义"。v0.2.0 的定义是
  **下载到本地临时目录后用内置解析器读取内容**，而不是仅在浏览器中打开；
  原因是模型必须拿到文本才能生成审核意见，且临时文件用后即删，
  比"浏览器打开给用户看"更符合自动化批处理的语义。
- **`file://` 场景的下载处理**：浏览器在 `file://` 下不触发下载事件，
  因此该协议下改为直接复制本地文件（代码中已注释说明）。HTTP/HTTPS 场景仍走
  Playwright 的真实 `expect_download`，并处理同名文件（追加 `-1`、`-2`）。
- **一个真实的性能坑（已修）**：Edge 每次下载都会自行打开 `edge://downloads-hub/`
  内部页，原先的"关闭新开标签页"清理逻辑去关它会阻塞约 7 秒；
  现已识别并忽略浏览器内部页（`edge:`/`chrome:`/`about:`/`devtools:`），
  本地 HTTP 站点整轮耗时从 **137 秒降到 14 秒**。
- **部分失败语义**：单个文件解析失败只让该文件失败并提示，
  只有全部文件都不可读时才把任务记为 failed——比"整任务失败并丢弃其余文件"更实用。
- **其他**：截图仅在任务抛异常时产生（任务级失败截图目录为空属正常）；
  `cleanup_temp()` 在运行中调用会跳过并返回 0，避免删掉正在使用的文件；
  结果文件按 `任务名_时间戳.md` 命名，不覆盖历史结果。
- 定时触发用后端线程 + `schedule` 库（配置 `schedule_enabled` / `schedule_times`）；
  **开机自启未自动写注册表**，改为在文档中指引用户把快捷方式放入系统「启动」文件夹——
  自动改注册表对一个"绿色便携"定位的程序过于侵入。

### 任务五 P3：技能市场

**实现**（`marketplace.py` + 设置窗口「技能市场」Tab）

  已安装徽标）、详情弹窗、安装/卸载按钮、空状态与加载状态、离线提示。

**关键决策与调整**
- **一处必须偏离任务书文字的地方**：任务书写"用上次同步的 `pushed_at` 做增量更新"，
  但 GitHub 仓库搜索**没有 `pushed_at:` 限定符**，照抄请求会返回 422。
  实现改用真实可用的 `pushed:>=YYYY-MM-DD`，并在代码注释中说明了原因。
  若增量结果打满单页则退化为全量刷新。
- **缓存失败不写 `synced_at`**：这样一次限流失败不会被固化成"已同步"状态，
  下次打开仍会重试；降级返回快照时置 `offline=true` 并附中文原因。
- **依赖不自动 pip 安装**：任务书 5.3 写"安装依赖"。实现改为**只提示不自动安装**，
  理由是自动 pip 安装第三方依赖等于以用户权限执行任意包的安装脚本，风险过高。
  依赖清单已记入注册表并展示给用户。
- **不引入 npm/PyPI 网络安装**：任务书写"优先检查是否已发布到 npm 或 PyPI"。
  实现为：解析并记录 `publish.npm`/`publish.pypi` 来源信息，
  但**实际落盘统一用 GitHub 源码 tarball**；若技能只发布了 npm/PyPI 而无源码，则明确失败并说明原因。
  理由同上（可控性与可审计性）。
- **解压安全加固**：逐成员检查绝对路径、`..`、越界符号链接与设备文件，
  再用 `tarfile` 的 `filter="data"` 二次加固；已用含 `../escaped.txt` 的构造 tarball
  验证目录穿越被拦截且包外没有写入。
- **卸载保留验证缓存**：注册表条目与技能目录被移除并回读确认，但该仓库的
  `skill.json` 验证缓存保留（避免下次打开市场重复请求，属节省 API 限额的取舍），
  卸载返回的 message 中已明确说明。
- **本地分页的"最佳匹配"是近似**：GitHub 的 best-match 排序无法离线复现，
  本地切片按"星数 + 最近推送"近似；在线关键词搜索仍用 GitHub 的真实排序。
- **技能运行期加载器未接线**：任务书 5.3 列出"可注册命令/UI 面板/自动化钩子/文件解析扩展"。
  v0.2.0 完整实现的是**发现 → 验证 → 详情 → 安装 → 卸载 → 注册表**这条链路，
  运行期把技能命令真正挂到 `/` 指令表的加载器只定义了接口与注册表字段，尚未接线。
  这是本次最明确的未完成项，已在变更日志与技能指南中说明。
- **签名验证**：记录了 tarball 的 sha256 供校验，但未实现发布者签名校验
  （技能生态尚未建立密钥分发机制）。

**关键决策与合规发现（如实报告）**
- **体积与合规的双重优化**：定位到后端 976MB 的根因是 `pyxtxt` 的 `estrattori` 子包
  在 `__init__` 里用 `os.listdir` 自动导入同目录全部解析器 → 打包必须整目录 →
  连带引入 easyocr→torch/torchvision/scipy/cv2/skimage/numba。
  改写 `file_parser.py` 为按格式直接解析后，**后端 976MB → 178MB**。
- 许可证扫描发现的**真实合规风险**（已在许可证文档中写明处理建议）：
  - `PyMuPDF` 为 **AGPL-3.0 / Artifex 商业许可二选一**，由 pdf 解析引入；
  - pyxtxt 依赖链原有 `extract-msg`/`pcodedmp`（GPL-3.0）、`RTFDE`/`python-bidi`/
    `pygame`/`pynput`（LGPL）——**移除 pyxtxt 后这些已不再随发布物分发**；
  - `PyInstaller` 的 GPLv2 带官方例外，明确允许打包分发专有程序，无需担心。
  - **结论**：个人使用与组织内部使用不触发著佐权义务；对外分发需处理 PyMuPDF 的 AGPL，
    或改用宽松许可的 PDF 实现（`pypdf`/`pdfminer.six`）。
- **日志脱敏**不只写进文档，而是落在代码里（`_redact()`、`files` 只记文件名）。

## 四、实现过程中对任务书的调整与原因（汇总）

| 任务书要求 | 实际做法 | 原因 |
| --- | --- | --- |
| rcedit 统一处理所有可执行文件 | 后端改用 PyInstaller `version`/`icon` | rcedit 会丢掉 PyInstaller 追加的 PKG 归档，后端无法启动（已复现） |
| 上下文窗口按模型训练长度决定 | 取"请求值与训练窗口的较小者" | 直接用训练窗口会让 KV Cache 膨胀到十几 GB，纯 CPU 不可用 |
| 自动化安装依赖 / 检查 npm、PyPI 后安装 | 解析并展示依赖，**不自动安装**；落盘统一用 GitHub tarball | 自动安装等于以用户权限执行第三方安装脚本，风险过高 |
| 执行 prepare 脚本前清洗敏感环境变量 | **不执行** prepare 脚本，只提示 | 同上，安全优先；`_sanitized_env()` 已实现备用 |
| 技能 API 包含可注册命令/UI 面板/自动化钩子 | 只完成发现/验证/详情/安装/卸载/注册表；加载器接口已定义未接线 | 时间与风险权衡；明确列为未完成项 |
| 虚拟滚动、消息折叠、历史搜索 | 未实现 | 属"考虑"项；改造风险高于收益，已记入已知限制 |
| 开机自启通过注册表或启动文件夹实现 | 仅文档指引用户手动放入启动文件夹 | 自动改注册表与"绿色便携"定位冲突 |
| 自动更新、离线安装包 | 离线包已支持（`-IncludeModels`）；自动更新未实现 | 需要版本清单服务与签名，超出本次范围 |
| 代码签名 | 预留 `-Sign` 钩子与 `signtool` 调用，仓库不含证书 | 需采购证书 |
| 干净虚拟机/低配/压力/泄漏测试 | 未做，已在第三节列明 | 无可用测试环境；已用自检与真实端到端覆盖主要链路 |

## 六、后续版本建议（按性价比排序）

1. **对外分发前处理 PyMuPDF 的 AGPL 义务**：改用 `pypdf`/`pdfminer.six` 可同时解决
   合规问题并再减约 20MB。若仅自用/内部使用则无需处理。
2. **技能运行期加载器接线**：把技能声明的命令挂到 `/` 指令表，让"市场"真正产出能力。
