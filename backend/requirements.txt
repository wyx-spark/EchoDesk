# 说明：v0.2.0 起不再依赖 pyxtxt。原因：
#   1) 其 estrattori 子包用 os.listdir 自动导入同目录全部解析器，打包时必须整目录
#      收集，否则启动即报 FileNotFoundError；整目录收集又会连带引入
#      easyocr/torch/torchvision/scipy/cv2/skimage/numba，后端体积膨胀到近 1GB；
#   2) 其依赖链含 AGPL（PyMuPDF 之外）与 GPL/LGPL 组件（extract-msg、pcodedmp、
#      RTFDE、python-bidi、pygame、pynput），对外分发会产生著佐权义务。
# 现改为按格式直接使用轻量、宽松许可的解析库（见 backend/file_parser.py）。

# download_utils.py 也会（tqdm）。直接 import 的包必须直接声明，
# 否则依赖关系是"运气"而不是"约束"。由 tools/check_requirements.py 门禁。
requests                  # 技能市场 HTTP（Apache-2.0）

# v0.2.1 发布复核新增：**被 pypdf 可选使用、但本项目的功能依赖它**。
#   * backend/file_parser.py 对"只设了权限密码（空口令）"的 PDF 会调 reader.decrypt("")；
#     pypdf 的加密提供者优先用 cryptography，缺失时退回到只支持 RC4 的纯 Python 实现，
#     AES 加密的这类 PDF 就解不开 —— 属用户可见的功能差异。
#   * 为什么必须显式声明：PyInstaller 是按**打包机环境**分析的，开发机装了
#     cryptography（来自 msoffcrypto-tool，一个与发布物无关的旧包），
#     于是它被**打进发布物却没出现在 `docs/THIRD_PARTY_LICENSES.md` / `docs/SBOM.json` 里**
#     —— 对外分发时就是"未声明的第三方组件"。声明后干净环境与发布物口径一致。
#     （`tools/check_bundled_packages.py` 专门比对这件事。）
cryptography              # 加密 PDF 读取（pypdf 的可选加密提供者；Apache-2.0 OR BSD-3-Clause）

# v0.2.1（任务书 1.3）PDF 解析由 pymupdf 换成 pypdf：
#   * pymupdf 是 AGPL-3.0（或 Artifex 商业许可），对外开源分发会产生著佐权义务，

#   * 代价：不处理无文本层的扫描件，复杂排版阅读顺序还原弱于 MuPDF。
xlrd                      # .xls（BSD）
